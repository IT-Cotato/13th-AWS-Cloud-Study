# **Chapter 23: 네트워크 트래픽 로깅 서비스 파악하기**

## 23.1 네트워크 트래픽 로깅 서비스, VPC 플로우 로그란?

**VPC 플로우 로그의 개념**

<aside>

VPC의 네트워크 인터페이스에서 송수신되는 **IP 트래픽 요약 정보**를 수집하는 기능 .

AWS에서 네트워크 인터페이스를 ENI(Elastic Network Interface)라고 하는데, 대표적으로 EC2와 RDS, ELB에 ENI가 할당이되며 VPC endpoint, RDS, Elasticache 등에도 ENI가 할당이 된다.

</aside>

- 저장소: **Amazon S3** 또는 **Amazon CloudWatch Logs**

---

**VPC 플로우 로그 동작 흐름**

```json
사용자 → VPC 내부 EC2 인스턴스 접근
  → 네트워크 인터페이스에서 트래픽 정보 수집
  → 플로우 로그 레코드 생성
  → S3 또는 CloudWatch Logs에 저장
```

→ 저장된 로그로 **네트워크 구성이 의도대로 동작하는지 검증** 가능

---

**VPC 플로우 로그의 활용 목적 3가지**

**① 보안 진단**

- 보안 그룹이 의도한 트래픽만 허용하는지 확인
- 악성 IP와의 통신 여부, 의심스러운 포트 접근 탐지
- 거부(REJECT)된 트래픽 분석
- DDoS 등 비정상 트래픽 탐지

**② 네트워크 장애 분석**

- 특정 서버 접속 불가 원인 파악
- 요청이 어느 지점까지 도달했는지 추적
- 보안 그룹 또는 네트워크 ACL에 의한 차단 여부 확인
- 예상 밖의 통신 경로 확인

**③ 네트워크 모니터링**

- 트래픽 출발지/목적지 파악
- 통신량이 많은 서버·인터페이스 탐지
- 특정 시간대의 비정상 활동 확인

## **23.2 VPC 플로우 로그 살펴보기**

#### 기본 포맷 (공백 구분, 1줄 = 1레코드)

```
version account-id interface-id srcaddr dstaddr srcport dstport protocol packets bytes start end action log-status
```

예시:

```
2 412213214 eni-xxxx xx.xx.xx.xx xx.xx.xx.xx 22 31587 6 4 333 1743813123 1743813123 ACCEPT OK
```

## 23.2.1 VPC 플로우 로그 필드

#### 필드별 설명

| 필드 | 설명 |
| --- | --- |
| **version** | 로그 형식 버전 (기본 필드만 쓰면 보통 2, 커스텀 필드 추가 시 더 높은 버전) |
| **account-id** | ENI를 소유한 AWS 계정 ID (12자리) |
| **interface-id** | 트래픽이 기록된 ENI ID (예: `eni-01dd0ee7c2c534304`). EC2는 ENI를 여러 개 가질 수 있어 실제 발생 인터페이스 식별에 사용 |
| **srcaddr / dstaddr** | 출발지/목적지 IP. 비정상 외부 접근, 내부 리소스 간 예기치 못한 통신, 악성 IP 연결, 잘못된 경로 확인에 활용 |
| **srcport / dstport** | 출발지/목적지 포트. 목적지 포트로 접근한 서비스 추정 가능 |
| **protocol** | IANA 프로토콜 번호 (1=ICMP, 6=TCP, 17=UDP) |
| **packets / bytes** | 전송된 패킷 수/바이트 수. 통신량 추정 → DDoS, 비정상 파일 전송, 데이터 유출, 포트 스캔, 앱 오작동으로 인한 과도한 요청 의심 지표 |
| **start / end** | UNIX 시간 형식의 통신 시작·종료 시각. `통신 시간 = end - start`로 계산 가능. 특정 시간대 반복 트래픽 분석에 활용 |
| **action** | `ACCEPT`(허용) / `REJECT`(거부). ACCEPT는 네트워크 계층에서 허용됐다는 뜻일 뿐, 애플리케이션이 정상 응답했다는 의미는 아님 |
| **log-status** | `OK`(정상 생성) / `NODATA`(기록할 트래픽 없음) / `SKIPDATA`(일부 레코드 누락·문제 발생, 반복 시 수집 환경·처리 한도 점검 필요) |

**포트별 대표 서비스 (dstport 참고용)**

| 포트 | 서비스 |
| --- | --- |
| 22 | SSH |
| 25 | SMTP |
| 53 | DNS |
| 80 | HTTP |
| 443 | HTTPS |
| 3306 | MySQL |
| 5432 | PostgreSQL |

→ 흔치 않은 포트에 반복 접근 시 보안상 의심 활동으로 간주 가능

**REJECT 로그 발생 시 점검 항목**

- 보안 그룹 인바운드/아웃바운드 규칙
- 네트워크 ACL
- 출발지/목적지 IP, 대상 포트, 프로토콜

## **23.3 실습: VPC 플로우 로그 생성 및 확인**

#### 전체 흐름

```
EC2 인스턴스 + VPC 생성
  → S3 버킷 생성
  → VPC 플로우 로그 생성 (CloudFormation)
  → EC2 인스턴스로 트래픽 발생
  → S3 버킷에서 로그 파일 확인
  → 로그 다운로드 및 분석
```

#### 23.3.1 CloudFormation 리소스 정의

```yaml
VPCFlowLogs:
  Type: AWS::EC2::FlowLog
  Properties:
    LogDestinationType: s3
    LogDestination: !GetAtt FlowLogsBucket.Arn
    ResourceId:
      Ref: VpcId
    ResourceType: VPC
    TrafficType: ALL
    Tags:
      - Key: Name
        Value: !Sub ${SystemName}-${EnvName}-flowlogs
```

| 속성 | 설명 |
| --- | --- |
| `Type` | `AWS::EC2::FlowLog` — 플로우 로그 리소스 생성 |
| `LogDestinationType` | 로그 저장 위치 유형 (`s3` 사용) |
| `LogDestination` | 저장할 S3 버킷의 ARN |
| `ResourceId` | 모니터링 대상 리소스 ID (여기선 VPC ID) |
| `ResourceType` | `VPC` / `Subnet` / `NetworkInterface` / `TransitGateway` / `TransitGatewayAttachment` 중 선택 |
| `TrafficType` | `ACCEPT`(허용만) / `REJECT`(거부만) / `ALL`(전체) — 실습에서는 `ALL` 사용 |

#### 23.3.2 콘솔에서 확인하기

1. VPC 콘솔 이동 → 대상 VPC 선택
2. **플로우 로그** 탭에서 생성된 로그 확인
3. 확인 가능 정보: 플로우 로그 ID, 필터 유형, 로그 대상 유형·위치, 대상 리소스, 생성 상태

#### 트래픽 생성 (로그 수집 트리거)

플로우 로그는 실제 통신이 발생해야 기록되므로:

```bash
curl http://example.com
sudo yum update -y
```

위 명령으로 EC2-외부 네트워크 간 트래픽을 인위적으로 발생시킬 수 있음

#### S3에서 로그 확인

1. 플로우 로그의 대상 S3 버킷 이동
2. 생성된 로그 객체 확인 → 다운로드
3. `.gz` 압축 해제 → 텍스트 로그 분석
4. 결과 예시:

```
2 xxxxxxxx eni-01dd0ee7c2c534304 ... ACCEPT OK
2 xxxxxxxx eni-01dd0ee7c2c534304 ... REJECT OK
```
