이 장에서는 NoSQL 데이터베이스의 특징과 AWS에서 제공하는 NoSQL 데이터베이스인 아마존 다이나모DB를 상세히 살펴봅니다. 다이나모DB의 장점, 제약사항, 관계형 데이터베이스인 아마존 RDS와의 차이점, 그리고 실제 활용 방법에 대해 학습하여 효율적인 데이터베이스 선택과 활용을 돕는 것이 목적입니다.

### **16.1 유연한 NoSQL 데이터베이스 서비스, 아마존 다이나모DB란?**


> **DynamoDB**는 AWS에서 제공하는 **서버리스** 기반 Key-Value 형식의 NoSQL 데이터베이스입니다.
AWS에서 2004년 아마존 닷컴의 대용량 트랙픽으로 인한 전체 서버다운 문제를 개선하기 위해 만들어진 DB입니다.
> 

NoSQL은 SQL을 사용하지 않으며 고정된 스키마가 없는 **비관계형 데이터베이스**입니다. 데이터를 고유한 **키-값** 형식이나 JSON 형태로 저장하며, 단순한 구조로 인해 높은 **확장성**과 빠른 처리 속도를 제공합니다. 이는 실시간 데이터 분석, IoT, 모바일 애플리케이션 등 대규모 데이터 처리 작업에 적합합니다.

NoSQL 데이터베이스의 주요 특징은 다음과 같습니다

- **확장성**: 수평적 확장이 용이하여 서버 추가를 통해 데이터를 처리할 수 있습니다.
- **유연한 스키마**: 고정된 스키마 없이 다양한 형식의 데이터를 저장할 수 있습니다.
- **고성능**: 대용량 데이터 처리와 높은 읽기/쓰기 성능을 제공합니다.
- **분산 처리**: 데이터를 여러 서버에 분산 저장하여 장애 내성과 높은 가용성을 보장합니다.
- **빅데이터 처리 적합**: 비정형 및 대규모 데이터를 효율적으로 처리합니다.

아마존 다이나모DB는 이러한 NoSQL의 특징을 가지며, 특히 실시간 데이터 처리와 빠른 읽기/쓰기에 강점을 보입니다. 구체적인 장점은 다음과 같습니다 

- **완전 관리형**
- **고가용성 및 확장성**
- **무제한 스케일링**
- **초저지연성**
- **내구성**
- **보안 통합**
- **서버리스 모델**

다이나모DB는 **아마존 API 게이트웨이 및 AWS 람다와 연동하여 서버리스 환경 구축에 사용**됩니다. 아마존 RDS는 VPC 생성 및 인스턴스 유형, 스토리지 용량 조정 등 복잡한 설정이 필요하지만, 다이나모DB는 이러한 복잡한 설정 없이 리전 단위로 관리되며, OS 패치 등 정기 유지보수를 AWS가 직접 처리합니다. 이를 통해 개발자는 인프라 유지보수 부담 없이 개발에 집중할 수 있습니다 



### **16.2 유연한 NoSQL 데이터베이스 서비스, 아마존 다이나모DB 살펴보기**

아마존 다이나모DB는 유연한 NoSQL 데이터베이스이지만, 특정 **유스 케이스**에 적합하며 제약 사항이 존재합니다. 특히 **OLAP (Online Analytical Processing)**와 같은 데이터 분석 처리에는 적합하지 않습니다. 다이나모DB는 **키-밸류** 형태의 데이터베이스이기 때문에 다차원적인 분석이나 복잡한 쿼리에는 한계가 있습니다. OLAP는 시장 분석, 성과 관리 등 대규모 데이터를 분석하는 기법으로, 아마존 다이나모DB는 이러한 목적에 부합하지 않습니다


여기서 OLAP는 다차원적 정보를 관련자들이 공유해 빠르게 분석하는 과정을 뜻하며, 이 과정에서 사용되는 도구가 OLAP 툴입니다.


반면, **OLTP (On Line Transaction Processing)**는 주로 트랜잭션 처리 및 실시간 데이터 읽기/쓰기 작업에 중점을 둡니다. OLTP는 소규모 데이터를 대량으로 처리하는 데 탁월하며, 아마존 다이나모DB에 적합합니다. 쇼핑몰 결제, 발송 처리와 같은 작업에 활용될 수 있습니다 

아마존 다이나모DB의 주요 제약사항은 다음과 같습니다

- **항목당 크기 상한**: 항목당 최대 400KB로, 큰 데이터를 직접 저장하기에는 적합하지 않습니다.
- **트랜잭션 제약**: 단일 트랜잭션 내에서 최대 100건의 개별 작업만 지원합니다. 아마존 RDS가 수천에서 수백만 건의 트랜잭션을 처리할 수 있는 것에 비하면 적은 양입니다
    - **트랜잭션**: 여러 프로세스를 하나의 단위로 묶어 처리하는 것을 의미합니다. 모든 작업이 성공해야 트랜잭션이 완료되며, 중간에 실패하면 이전에 수행된 모든 작업을 취소하여 데이터베이스의 무결성을 보장합니다
- **검색 조건의 유연성 제약**: 기본키 또는 보조 인덱스(글로벌 보조 인덱스, 로컬 보조 인덱스)에 크게 의존하므로 SQL의 유연한 검색 패턴에 비해 제약이 있습니다.
- **JOIN 제약**: 여러 테이블을 연결하여 데이터를 검색하는 JOIN 연산이 지원되지 않습니다. 복수 테이블을 취급할 수는 있지만, JOIN은 불가능합니다. 따라서 여러 쿼리를 실행하여 데이터를 결합하거나, **싱글 테이블** 디자인 패턴을 사용하여 데이터를 취득해야 합니다

 

**아마존 다이나모DB와 아마존 RDS 비교** 

| 유형 | 아마존 다이나모DB | 아마존 RDS |
| --- | --- | --- |
| **유형** | NoSQL | SQL (관계형) |
| **검색 조건** | 사전에 지정된 키 또는 인덱스로만 검색 가능 | SQL 문으로 자유롭게 검색 가능 |
| **검색 처리** | JOIN 연산 미지원, 복잡한 검색 처리 불가능 | JOIN 연산을 통한 복잡한 검색 처리 가능 |
| **확장성** | 높은 확장성(오토 스케일링), 많은 트래픽 처리 가능 | SQL 기반 쿼리 처리 우수, 리드 복제본 생성 등 스케일에 추가 설정 필요 |
| **사용 사례** | 실시간 애플리케이션, 모바일, IoT 데이터 관리 | 복잡한 관계와 일관된 트랜잭션 처리, 비즈니스 및 금융 시스템 |

이러한 제약 사항들을 고려하여 아마존 다이나모DB와 아마존 RDS 중 어떤 데이터베이스를 사용할지 신중하게 선택해야 합니다.

### **16.2.2 유연한 NoSQL 데이터베이스 서비스, 아마존 다이나모DB 구성 요소**

아마존 다이나모DB는 데이터의 저장 및 분산을 효율적으로 관리하기 위해 여러 구성 요소를 사용합니다.

1. **파티션과 키**
    
    
    - **파티션**: 다이나모DB 데이터가 저장되고 분산되는 물리적인 단위입니다.
    - **파티션 키**: 데이터가 어느 파티션에 저장될지 결정하는 기준입니다.
    - **정렬 키**: 같은 파티션 내에서 데이터를 정렬하는 기준입니다. 정렬 키가 설정되면 데이터는 물리적으로 가깝게 배치되어 효율적인 조회 및 정렬이 가능해집니다.
    - **기본키**: 데이터를 고유하게 식별하는 키로, 파티션 키 단독 또는 파티션 키와 정렬 키의 복합 키로 구성됩니다. 데이터 읽기/쓰기 작업은 기본키를 지정하여 수행됩니다.
2. **보조 인덱스** 
    
    !스크린샷 2026-06-27 오후 12.16.19.png
    
     테이블의 파티션 키와 정렬 키만으로 충분하지 않은 다양한 검색 패턴을 지원하기 위해 사용됩니다.
    
    - **글로벌 보조 인덱스 (Global Secondary Index, GSI)**: 기본 테이블과는 다른 파티션 키와 정렬 키를 가질 수 있습니다. 이는 테이블 작성 후 설정할 수 있습니다.
    - **로컬 보조 인덱스 (Local Secondary Index, LSI)**: 기본 테이블과 동일한 파티션 키를 유지하면서 다른 정렬 키를 가질 수 있습니다. 이는 테이블 생성 시점에 설정해야 합니다.
3. **아마존 다이나모DB 엑셀러레이터 (DynamoDB Accelerator, DAX)** **p.10** 다이나모DB와 호환되는 완전 관리형 인메모리 캐시 서비스입니다. 밀리초에서 마이크로초 단위로 성능을 가속화하여 초저지연 읽기 작업을 가능하게 합니다.
    
    
    - **동작 방식**: 클라이언트가 DAX로 요청을 보내면, DAX 캐시에 데이터가 있는 경우 즉시 반환하고, 없는 경우 다이나모DB에 요청하여 결과를 캐시에 저장 후 클라이언트에게 반환합니다
4. **용량 모드**  다이나모DB 테이블의 처리 용량을 관리하는 방식입니다.
    - **온디맨드 모드 (On-Demand Mode)**: 읽기 및 쓰기 용량을 별도로 설정할 필요 없이, 자동으로 용량을 스케일링하여 트래픽을 처리합니다. 트래픽 예측이 어려울 때 유용합니다.
    - **프로비저닝 모드 (Provisioned Mode)**: 읽기 및 쓰기 용량을 수동으로 설정해야 합니다. 설정된 용량 내에서 트래픽을 처리하며, 오토스케일링을 사용하여 용량을 자동으로 조정할 수도 있습니다. 트래픽을 예측할 수 있을 때 유용합니다.
5. **가용성 및 내구성**  다이나모DB는 높은 가용성과 내구성을 제공합니다.

    
    - **다중 AZ 지원**: 동일한 리전 내 3개의 가용 영역(Availability Zone)에 데이터가 실시간으로 복제됩니다.
    - **글로벌 테이블 (Global Tables)**: 다중 리전에 걸쳐 테이블을 복제하여 빠른 읽기/쓰기와 높은 가용성을 제공합니다. 자체 복제 솔루션을 구축할 필요 없이 각 리전에 동일한 테이블을 생성하고 데이터 변경 내용을 모든 리전에 전파합니다. 이는 대규모 글로벌 애플리케이션에 적합하며, 사용자가 어디에 있든 낮은 대기 시간으로 데이터를 제공할 수 있습니다

### **16.3 아마존 다이나모DB 활용하기**

아마존 다이나모DB 테이블을 생성하고, AWS 람다 함수를 이용해 해당 테이블의 데이터를 호출하는 방법을 다룹니다.

### **16.3.1 AWS 람다 함수로 아마존 다이나모DB 테이블 데이터를 호출해보기**

1. **IAM 역할 추가**: 람다 함수가 다이나모DB 테이블에 접근할 수 있도록 IAM 역할에 권한을 할당합니다.
    - `Service`는 `lambda`로 지정합니다.
    - `AmazonDynamoDBFullAccess` 정책은 다이나모DB에 대한 전체 접근 권한을 부여하고, `AWSLambdaDynamoDBExecutionRole`은 다이나모DB 스트림에 대한 목록 및 읽기 접근 권한을 부여합니다.
2. **람다 함수 생성**: 다이나모DB 테이블에서 데이터를 호출하는 람다 함수를 생성합니다.
    - `GetDataLambdaFunction`이라는 함수를 `AWS::lambda::Function` 타입으로 정의합니다.
    - `Code` 섹션에는 `boto3` 라이브러리를 사용하여 다이나모DB 테이블(`gr-product-db`)을 참조하고 `scan()` 메서드로 데이터를 스캔하는 파이썬 코드를 포함합니다. 스캔된 데이터는 키-밸류 형태로 반환됩니다.
    - `Role`에는 위에서 생성한 IAM 역할의 ARN을 연결하여 람다 함수가 다이나모DB 테이블에 접근할 수 있도록 합니다.
3. **다이나모DB 테이블 생성**: `MyDynamoDBTable`이라는 다이나모DB 테이블을 `AWS::dynamodb::Table` 타입으로 정의합니다.
    - `TableName`은 `gr-product-db`로 지정합니다.
    - `AttributeDefinitions`에는 파티션 키로 `id` (문자열 타입)를 정의합니다.
    - `KeySchema`에는 기본키로 `id`를 `HASH` 타입으로 지정합니다.
    - `BillingMode`는 `PAY_PER_REQUEST` (온디맨드 모드)로 설정하여 사용량에 따라 비용을 지불하도록 합니다.

### **16.3.2 UI로 불러와 AWS 람다 함수로 아마존 다이나모DB 테이블 데이터를 호출해보기**

1. **클라우드포메이션 스택 생성**: 파라미터 설정 없이 기본값을 유지한 채 클라우드포메이션 스택을 생성합니다.
2. **다이나모DB 항목 생성**:
    - 다이나모DB 콘솔에서 생성된 테이블(`gr-product-db`)을 확인하고, `id`, `name`, `description` 속성을 가진 항목을 생성하여 더미 데이터를 삽입합니다. `id`는 파티션 키로 설정됩니다.
3. **람다 함수 실행**:
    - AWS 람다 콘솔에서 생성된 람다 함수(`gr-product-GetData`)를 선택하고 `Test` 기능을 사용하여 이벤트를 생성한 후 함수를 실행합니다.
    - 함수 실행 결과로 다이나모DB 테이블에 추가한 항목 데이터가 키-밸류 형태로 반환되는 것을 확인할 수 있습니다.
