## 20.1 인프라 관리 서비스, AWS 시스템 관리자란?

> AWS 시스템 관리자는 EC2 인스턴스 서버를 효율적으로 관리할 수 있는 도구이다.
> 

### AWS Systems Manager의 주요 기능

- EC2 인스턴스, 온프레미스 서버, 컨테이너 등의 운영을 자동화
- 운영 체제 및 애플리케이션 패치 관리
- 애플리케이션 설정 및 환경 변수를 중앙에서 관리
- SSH/RDP 없이 원격 명령 실행 및 서버 액세스

## 20.2 인프라 관리 서비스, AWS 시스템 관리자 살펴보기

AWS 시스템 관리자는 다양한 관리 기능 제공한다. 

#### 1. 작업 관리 서비스

| 기능 | 역할 |
| --- | --- |
| 탐색기 | 계정/리전 전체 운영 데이터를 한눈에 보여줌 |
| 옵스센터 | 운영 이슈를 한 곳에 모아서 상황 파악 + 해결 지원 |
| 클라우드워치 대시보드 | 리소스 지표/경보를 커스텀 화면으로 시각화 |
| 인시던트 관리자 | 장애 발생 시 완화/복구 지원 |

#### 2. 애플리케이션 관리 서비스

| 기능 | 역할 |
| --- | --- |
| 애플리케이션 관리자 | 앱 단위로 AWS 리소스 문제를 조사/해결 |
| 앱컨피그 | 애플리케이션 설정값을 생성/배포 |
| 파라미터 스토어 | 설정값·비밀값을 안전하게 계층 구조로 저장 |

#### 3. 변경 관리 서비스

| 기능 | 역할 |
| --- | --- |
| 변경 관리자 | 인프라 변경 요청/승인/구현 흐름을 관리 |
| 자동화 | EC2 등 리소스 유지보수 작업을 자동화 |
| 일정 변경 | 특정 작업이 언제 실행/차단될지 스케줄 지정 |
| 유지 관리 기간 | 패치·업데이트 등 중단 가능성 있는 작업의 시간대 정의 |

#### 4. 노드 관리 서비스

| 기능 | 역할 |
| --- | --- |
| 플릿 관리자 | 서버에 직접 접속 안 해도 인스턴스들 관리 |
| 규정 준수 | 컴플라이언스 데이터 모니터링 |
| 인벤토리 | 컴퓨팅 환경 전체 가시성 제공 |
| 하이브리드 활성화 | EC2 + 온프레미스 환경 통합 관리 |
| **세션 관리자** | **SSH 키 없이 EC2에 원클릭 보안 접속** ← 실무에서 자주 씀 |
| 명령 실행 | 여러 인스턴스에 원격 명령 안전하게 실행 |
| 상태 관리자 | 인스턴스를 정의된 상태로 자동 유지 |
| 패치 관리자 | 보안 패치 자동화 |
| 배포자 | 패키지 생성 및 배포 |

### 20.2.1 애플리케이션 관리, 파라미터 스토어

> 파라미터 스토어는 애플리케이션 설정 및 암호화된 정보를 안전하게 저장하고 관리한다.
여러 시스템들의 환경 변수, 애플리케이션 구성, 암호, API 키 등의 보안 및 운영 데이터를 안전하게 저장하고 관리할 수 있도록 지원한다.
> 
- 구성 정보 및 데이터 저장
- AWS KMS 기반 암호화 지원
- 버전 관리 및 변경 이력 추적

### 20.2.2 변경 관리, 자동화

> 자동화는 AWS 리소스에서 반복적으로 수행해야 하는 운영 작업을 자동화하여 수작업 부담을 줄이고 운영 효율성을 향상하는 역할을 한다.
> 
- 운영 작업 자동화
- 자동 복구 및 장애 대응
- 템플릿 기반 실행
    - 미리 정의된 템플릿을 사용하여 운영 작업을 표준화
    - 예를 들어, EC2 인스턴스를 특정 태그 기반으로 자동 시작 또는 중지

### 20.2.3 노드 관리, 플릿 관리자

> 플릿 관리자는 서버에 원격으로 개별 접속하지 않고도 AWS 및 온프레미스 환경에서 실행 중인 다수의 인스턴스를 한 화면에서 통합 관리할 수 있도록 지원한다.
> 
- 다수의 인스턴스 상태를 대시보드 형태로 한눈에 파악
- 인스턴스별 메타데이터, 태그, 소프트웨어 인벤토리 조회
- 콘솔에서 직접 파일 탐색, 프로세스 확인, 서비스 재시작 등 기본 운영 작업 수행
- 여러 인스턴스를 대상으로 일괄 작업(Runbook, 명령 실행 등) 실행 가능
- 규정 준수 상태와 패치 현황을 함께 확인 가능

### 20.2.4 노드 관리, 세션 관리자

> 세션관리자는 SSH 키나 RDP를 사용하지 않고도 AWS 콘솔 또는 CLI를 통해 인스턴스에 원격으로 접속할 수 있도록 지원한다.
> 
- SSH/RDP 없이 원격 서버 관리
- IAM 기반 액세스 제어 및 로깅
- 보안 그룹 및 VPN 설정 필요 없음

### 20.2.5 노드 관리, 명령 실행

> 명령 실행은 SSH 접속 없이도 다수의 관리형 노드에 대해 안전하게 원격 명령을 실행하고 구성을 관리할 수 있도록 지원한다.
> 
- 스크립트 또는 명령을 다수의 인스턴스에 동시에 원격 실행
- 실행 결과 및 출력 로그를 콘솔, S3, CloudWatch Logs에서 확인 가능
- IAM 정책 기반으로 명령 실행 권한을 세밀하게 제어
- 사전 정의된 문서 또는 사용자 정의 스크립트 활용 가능
- 소프트웨어 설치, 설정 변경, 로그 수집 등 반복 운영 작업에 활용

### 20.2.6 노드 관리, 패치 관리자

> 패치 관리자는 운영체제 및 애플리케이션의 보안 패치를 자동으로 스캔하고 적용하여, 관리형 노드를 최신 보안 상태로 유지하는 프로세스를 자동화한다.
> 
- 인스턴스의 패치 준수 상태를 자동으로 스캔 및 보고
- 패치 기준선을 정의하여 승인된 패치만 자동 적용
- 유지 관리 기과 연동하여 지정된 시간대에만 패치 수행
- OS 및 주요 소프트웨어에 대한 패치 지원
- 패치 적용 전후 스냅샷/백업과 연계하여 롤백 대비 가

### 20.2.7 공유 리소스, 문서

> 문서는 시스템 관리자가 노드에서 수행할 작업을 정의한 실행 가능한 스크립트 또는 워크플로우로, Systems Manager의 여러 기능(자동화, 명령 실행, 세션 관리자 등)에서 공통적으로 참조되는 공유 리소스이다.
> 
- Command 문서: 명령 실행에서 사용하는 단발성 작업 정의
- Automation 문서: 자동화 워크플로우에서 사용하는 다단계 작업 정의
- AWS에서 제공하는 사전 정의(Public) 문서와 사용자가 직접 작성하는 사용자 정의(Custom) 문서로 구분
- JSON 또는 YAML 형식으로 작성 및 버전 관리
- 조직 내 여러 팀이 표준화된 운영 절차를 공유하고 재사용 가능
