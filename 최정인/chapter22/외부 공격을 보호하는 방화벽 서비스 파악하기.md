# Chapter 22. 외부 공격을 보호하는 방화벽 서비스 파악하기

### 22.1 **AWS WAF**(Web Application Firewall) **개념**

!스크린샷 2026-07-18 오후 9.56.26.png

**WAF란?**

> WAF(Web Application Firewall)는 흔히 말하는 웹 방화벽이다.
> 

웹방화벽은 웹 어플리케이션으로 통하는 트래픽을 모니터링 하여 필터링 또는 차단을 하며 웹 공격으로부터 보호해주는 역할을 한다.

WAF는 서비스의 구성 변경 없이 도입만으로 쉽고 빠르게 서비스의 안정성, 보안을 향상시킬 수 있는 장점이 있다.

단, 웹 어플리케이션을 보호하기 때문에 HTTP프로토콜을 사용하는 AWS리소스만 연결 가능하다

- **보안 그룹**: IP·포트 단위 네트워크 계층 제어. HTTP 요청 "내용"까지는 판단 불가.
- **AWS WAF**: 웹 요청 내용을 검사해 악성 요청 차단 (애플리케이션 계층).
- 연결 대상: CloudFront, ALB, 기타 웹 진입점.

| 구분 | 보안 그룹 | AWS WAF |
| --- | --- | --- |
| 제어 대상 | IP·포트 | HTTP 요청 내용 |
| 계층 | 네트워크 중심 | 애플리케이션 중심 |
| 목적 | 비허용 네트워크 접근 차단 | 악성 웹 요청 탐지/차단 |
| 예시 | 443 포트 허용 | SQL Injection 패턴 차단 |

#### **22.2 처리 흐름**

```
사용자 요청 → 보안 그룹(네트워크 허용 확인) → WAF(악성 요청 검사) → 정상이면 앱 전달
```

검사 결과는 CloudWatch에 기록 가능, 필요시 S3에 로그 저장.

### 22.2.1 WAF 주요 기능 5가지

1. **애플리케이션 공격 방어** — IP, HTTP 헤더, 요청 본문, URI, 국가, 특정 패턴 기준 차단 규칙
2. **IP 제한 무단 접근 차단** — 관리자 페이지 등 보호에 유용
3. **DDoS 대책** — 특정 IP의 일정 시간 요청 수 초과 시 차단 (**Rate-based Rule**)
4. **악성 봇 대책** — 정상 봇(검색엔진)은 허용, 스크레이퍼·스캐너는 차단
5. **계정 무단 로그인 방지** — 로그인 페이지 감시, 탈취 자격증명·비정상 패턴 탐지

### 22.2.2 관리형 규칙 (Managed Rules)

AWS가 사전 제공하는 규칙 세트. 직접 로직 작성 없이 선택 적용.

!스크린샷 2026-07-18 오후 9.58.33.png

| 규칙명 | 용도 | WCU | 적용 권장 |
| --- | --- | --- | --- |
| Admin protection | 관리 페이지 보호 | 100 | 환경에 따라 |
| Amazon IP reputation list | 위험 IP 차단 | 25 | **필수 권장** |
| Anonymous IP list | VPN/프록시 등 차단 | 50 | 환경에 따라 |
| Core rule set | 일반 웹 공격 방어 | 700 | **필수 권장** |
| Known bad inputs | 알려진 악성 입력 차단 | 200 | **필수 권장** |
| Linux OS | Linux 취약점 방어 | 200 | OS에 따라 |
| PHP application | PHP 취약점 방어 | 100 | 환경에 따라 |
| POSIX OS | POSIX 취약점 방어 | 100 | OS에 따라 |
| SQL database | SQL 공격 방어 | 200 | **필수 권장** |
| Windows OS | Windows 취약점 방어 | 200 | OS에 따라 |
| WordPress application | WordPress 취약점 방어 | 100 | 환경에 따라 |

**WCU (Web ACL Capacity Unit)**

- 규칙이 소비하는 처리 용량 단위
- Web ACL 1개 최대 **5,000 WCU**
- 교재 기준 기본 요금에 **1,500 WCU 포함**, 초과 시 추가 요금
- 필수 규칙부터 적용 → 이후 OS/프레임워크 전용 규칙 추가

### 22.2.3 커스텀 규칙 (Custom Rules)

관리형으로 안 되는 서비스 고유 조건 구현.

- **IP 세트**: 특정 IP/범위 묶어 허용·차단
- **규칙 빌더**: HTTP 헤더, 국가, IP, URI, 문자열, XSS, SQL Injection, 요청 크기 등 조합 (`AND`/`OR`/`NOT`)
- **규칙 그룹**: 여러 규칙을 묶어 재사용 (여러 Web ACL에서 공용)

### 22.3 실습: CloudFront + S3 정적 웹에 WAF 연결

**구성 흐름**

```
사용자 → CloudFront → CloudFront OAI → S3
```

WAF는 CloudFront에 연결되어 요청 검사.

**적용 관리형 규칙**: Amazon IP reputation list, Known bad inputs, SQL database

**스택 생성 순서**

```
WAF.yml → CloudFront.yml
```

⚠️ **CloudFront용 WAF는 글로벌 리소스 → 반드시 us-east-1(버지니아 북부)에 생성**

### 22.3.1 CloudFront에 WAF 도입 절차

**1) Web ACL 생성**

```yaml
WebACL:
  Type: AWS::WAFv2::WebACL
  Properties:
    DefaultAction:
      Allow: {}
    Scope: CLOUDFRONT
    VisibilityConfig:
      CloudWatchMetricsEnabled: true
      MetricName: !Sub ${SystemName}-${EnvName}-WebACLMetrics
      SampledRequestsEnabled: true
```

- `DefaultAction`: 어떤 규칙에도 안 걸리는 요청 기본 처리
- `Scope: CLOUDFRONT`: CloudFront용 WAF 지정
- `SampledRequestsEnabled`: 요청 표본 저장(분석용)

**2) 관리형 규칙 추가**

```yaml
Rules:
  - Name: AWS-AWSManagedRulesAmazonIpReputationList
    Priority: 0
    OverrideAction:
      Count: {}
    Statement:
      ManagedRuleGroupStatement:
        VendorName: AWS
        Name: AWSManagedRulesAmazonIpReputationList
    VisibilityConfig:
      CloudWatchMetricsEnabled: true
      MetricName: AWSManagedRulesAmazonIpReputationList
      SampledRequestsEnabled: true
```

**규칙 처리 방식**

- `Priority` 숫자가 **작을수록 먼저 평가**
- 일치하는 규칙 없으면 `DefaultAction` 적용
- 관리형 규칙은 기본적으로 차단 동작
- `OverrideAction: Count` → 차단 안 하고 **일치 횟수만 기록** (오탐 검증용, 운영 전환 시 제거)

**3) WAF 로그 저장**

```yaml
WAFLoggingConfiguration:
  Type: AWS::WAFv2::LoggingConfiguration
  Properties:
    ResourceArn: !GetAtt WebACL.Arn
    LogDestinationConfigs:
      - !GetAtt WAFLogBucket.Arn
```

- 로그 저장 대상 지정

### 22.3.2 콘솔에서 확인 가능한 정보

- **Web ACL 개요**: 허용/차단/Count/CAPTCHA·Challenge 처리 현황, 규칙·우선순위
- **규칙 화면**: 규칙 그룹별 동작 확인/수정(`View and edit`)
- **로깅 구성**: 로그 저장 대상·활성화 상태, S3로 상세 요청 분석
- **대시보드 & Threat Intelligence**: 트래픽/규칙/봇/DDoS 특성 분석. 약 2주간 트래픽 기반으로 IP 평판, DDoS, 봇 활동, 알려진 취약점 악용 분석

### WAF 배치 패턴 정리

**패턴 1: CloudFront + S3**

```
사용자 → CloudFront(WAF) → S3
```

진입점이 CloudFront 하나뿐 → CloudFront에만 WAF 적용이 일반적

**패턴 2: CloudFront + ALB**

```
사용자 → CloudFront → ALB → 웹 애플리케이션
```

- WAF 적용 위치 3가지: CloudFront만 / ALB만 / 둘 다
- 둘 다 적용하면 보안↑ but 비용↑
- ALB 직접 접근이 차단되어 있고 대부분 트래픽이 CloudFront 경유라면 CloudFront만으로도 효율적
