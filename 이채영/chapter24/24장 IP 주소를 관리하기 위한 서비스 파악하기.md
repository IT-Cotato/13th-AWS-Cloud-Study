# IP 주소를 관리하는 서비스, 관리형 접두사 목록 살펴보기

- 어떤 상황에서 관리형 접두사 목록을 사용해야 할까?

!KakaoTalk_20260724_171647656_02.jpg

- SSH 통신을 허용하는 IP 주소가 4개이면 보안 그룹에 4개의 IP 주소를 허용해야 한다.
- 하지만 이 IP 주소가 6개, 8개 그 이상으로 늘어나게 된다면 관리하기가 어려움
    - 각 IP 주소마다 별도의 규칙을 추가해야 하며, 이로 인해 규칙 수가 늘어나면서 보안 그룹 구성이 복잡해진다.
- 이런 상황에서 관리형 접두사 목록을 사용하면, 더 쉽게 보안 그룹과 라우팅 테이블을 관리할 수 있다.

!KakaoTalk_20260724_171647656_03.jpg

- 보안 그룹에 n개의 규칙이 추가되었다고 가정
- IP 주소는 사용 환경에 따라 20개에서 30개, 때로는 그 이상으로 늘어날 수 있다.
- 이런 많은 IP 주소를 보안 그룹에서 개별적으로 관리하고 지정하는 것은 매우 복잡하고 비효율적
- 관리형 접두사 목록을 사용한다면 체계적인 관리, 확장성, 재사용성, 가독성 향상 가능

!KakaoTalk_20260724_171647656_04.jpg

- 관리형 접두사 목록을 사용했을 때의 보안 그룹 규칙
- n개의 규칙에서 단 하나만의 규칙이 추가되었으며 이로 인해 규칙의 복잡성, 가시성, 유지보수의 부담이 줄어든다.

# 관리형 접두사 목록 활용하기

- 고객 관리형 접두사 목록을 생성해보고, 생성한 고객 관리형 접두사 목록을 보안 그룹에 추가해보자.

## 고객 관리형 접두사 목록을 생성해 보안 그룹에 추가해보기

> VPC.yml → AWS_Managed_Prefix_List.yml → Security_Group.yml 순서로 클라우드포메이션 스택을 생성해야 한다.
>

https://github.com/classmethodjaewook/aws-developer/tree/main/chapter24

1. 고객 관리형 접두사 목록 생성

```yaml
# AWS_Managed_Prefix_List.yml

  PrefixList:
    Type: AWS::EC2::PrefixList # 고객 관리형 접두사 목록 생성
    Properties:
      AddressFamily: IPv4 # IPv4 or IPv6의 IP 주소 타입 입력
      Entries: # 관리할 IP 주소 입력
        - Cidr: 1.2.3.4/32
        - Cidr: 1.3.2.4/32
        - Cidr: 1.4.2.4/32
        - Cidr: 1.5.3.5/32
      MaxEntries: 4 # 관리형 접두사 목록에 추가할 최대 IP 주소 수
      PrefixListName: !Sub ${SystemName}-${EnvName}-prefix
```

1. 보안 그룹에 고객 관리형 접두사 목록 추가

```yaml
# Security_Group.yml

      SecurityGroupIngress: # 허용할 IP 주소 설정
        - IpProtocol: tcp
          FromPort: 22
          ToPort: 22
          SourcePrefixListId: { "Fn::ImportValue": !Sub "${EnvName}-prefix" } # 고객 관리형 접두사 목록 추가
```

1. VPC 콘솔 화면에서 [관리형 접두사 목록] 클릭하여 생성된 고객 관리형 접두사 목록 확인

1. 고객 관리형 접두사 목록의 상세 설정 확인

- [연결] 클릭 - 어떠한 리소스에서 해당 고객 접두사 목록을 사용하는지 확인

1. 보안 그룹 확인
