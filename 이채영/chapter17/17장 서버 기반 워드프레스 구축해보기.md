# 서버 기반 워드프레스 구성도 이해하기

- 워드프레스를 활용한 블로그 플랫폼사이트를 구축해보자.
    - 워드프레스 : 블록, 쇼핑몰과 같은 다양한 웹 콘텐츠 제작이 가능한 콘텐츠 관리 시스템
- 보안성 : 프라이빗 서븟넷을 활용한 데이터 보호
- 성능 : ALB를 통한 부하 분산
- 확장성 : 트래픽 증가에 대비한 구조

!KakaoTalk_20260731_151409218.jpg

- 퍼블릭 서브넷에는 NAT 게이트웨이를 배치해 관리자가 SSM을 통해 EC2 인스턴스로 접속할 수 있게 한다.
- EC2 인스턴스는 프라이빗 서브넷에 배치해 관리자 이외에는 접속 불가능하도록 설정
- 사용자는 퍼블릭 서브넷에 생성된 로드 밸런서를 이용해 언드프레스에 접근
- RDS가 생성된 프라이빗 서브넷에는 NAT 게이트웨이, 인터넷 게이트웨이와 통하는 경로가 없으며, 오직 EC2 인스턴스와만 상호작용가능
- 관리자의 경우 RDS에 직접 접근하는 것이 불가능하므로 EC2 인스턴스를 경유해 접근해야 한다.

## 서버 기반 워드프레스 구축 단계

1. 클라우드포메이션으로 리소스 생성
2. EC2 인스턴스와 RDS for MySQL 연동
3. EC2 인스턴스에서 워드프레스 구성
4. 워드프레스 접속

> VPC.yml → IAM.yml → Security_Group.yml → EC2.yml → ALB.yml → RDS.yml 순서로 클라우드포메이션 스택을 생성해야 한다.
>

https://github.com/classmethodjaewook/aws-developer/tree/main/chapter17

- RDS.yml 파라미터에서는 데이터베이스 사용자의 암호 입력 (8자 이상)
- [다음]을 클릭해 클라우드포메이션 스택 생성

# EC2 인스턴스와 RDS for MySQL 연동하기

- 워드프레스에서는 사용자 정보를 포함해 게시글, 댓글, 워드프레스의 구성 설정 등 다양한 정보를 담고 있으므로 이런 정보를 데이터베이스에 저장해야한다.
- 이번 실습에서는 아마존 RDS를 워드프레스 데이터베이스로 사용한다.
- 워드프레스에서 아마존 RDS를 사용하려면 몇 가지 설정이 필요하다.
1. 생성한 EC2 인스턴스에서 세션 매니저를 사용해 접속한다.
- [Session Manager] - [연결]
1. EC2 인스턴스에 MySQL을 설치한다.

```bash
sudo yum install -y mysql
```

!image.png

1. EC2 인스턴스에 RDS for MySQL로 접근하기 위해 생성한 RDS의 엔드포인트를 확인한다.

!image.png

1. EC2 인스턴스에서 RDS로 접속 시도
- MYSQL_HOST에 RDS for MySQL의 엔드포인트 입력
- mysql 명령어로 RDS for MySQL에 접근 시도
- —user에는 데이터베이스 사용자 이름을 입력하고, —password에는 데이터베이스 사용자의 암호 입력
- wordpress : 접속하려는 데이터베이스 이름

```bash
export MYSQL_HOST=gr-product-rds.cfyoau0uc5kw.ap-northeast-2.rds.amazonaws.com
mysql --user=admin --password=데이터베이스 사용자의 암호 wordpress
```

# EC2 인스턴스에서 워드프레스 구성하기

1. EC2 인스턴스에서 Apache 설치
- EC2 인스턴스에서 아파치를 설치하고, 아파치 웹 경로인 /var/www/html에 아파치의 샘플 페이지 복사

```bash
sudo yum install -y httpd
sudo service httpd start
sudo cp /usr/share/httpd/noindex/index.html /var/www/html/index.html
```

1. 로드밸런서의 DNS를 이용해 브라우저에서 접근하면, 아파치 샘플 페이지가 표시되는 것을 확인할 수 있다.

!image.png

!image.png

1. 워드프레스 소프트웨어 다운로드
- wget 명령어로 워드프레스 소프트웨어를 내려받고 압축 해제
- 압축을 해제한 워드프레스 폴더로 이동해 기본 구성 파일의 사본 생성

```bash
sudo wget https://wordpress.org/latest.tar.gz
sudo tar -xzf latest.tar.gz
cd wordpress

sudo cp wp-config-sample.php wp-config.php
```

1. 워드프레스의 구성 정보를 변경한다.
- wp-config.php 파일을 편집해 워드프레스의 구성 정보를 변경한다.

```bash
sudo vi wp-config.php
```

- DB_NAME은 RDS for MySQL을 생성할 때 설정한 데이터베이스 이름인 wordpress를 입력한다.
- DB_USER는 워드프레스 사용을 위해 생성한 사용자 이름 입력
- DB_PASSWORD는 MySQL에서 생성한 사용자의 암호 입력
- DB_HOST에 RDS의 엔드포인트 입력
- 아래로 내려오면 define으로 시작하는 각종 키 설정가뱃을 확인할 수 있다.
1. 워드프레스에 필요한 애플리케이션 종속성 설치하고 워드프레스 파일을 웹 경로인 /var/www/html로 복사
- 웹페이지 테스트로 사용했던 아파치 샘플 파일은 rm 파일을 사용해 삭제하고, restart 명령어로 아파치를 재시작한다.

```bash
sudo amazon-linux-extras install -y lamp-mariadb10.2-php7.2 php7.2
cd ..
sudo cp -r wordpress/ /var/www/html
cd /var/www/html
sudo rm index.html
sudo service httpd restart
```

# 워드프레스에서 추가적으로 고려할 수 있는 사항들

## 도메인과 고속 콘텐츠 제공

!KakaoTalk_20260731_151409218_01.jpg

- 사용자가 알아보기 쉽게 도메인으로 전환할 필요가 있기 때문에 아마존 라우트53 사용
- 해외에서도 이용하는 사용자가 있다면 고속 콘텐츠를 제공할 필요가 있기 때문에 아마존 클라우드프론트 이용

## HTTPS와 로그 설정

!KakaoTalk_20260731_151409218_02.jpg

- 라우트53에 도메인 등록, AWS ACM을 이용해 인증서 발급받기
- 발급받은 인증서를 로드 밸런서에 등록
- 로드 밸런서에 액세스 로그를 설정해 로드 밸런서를 통해 접근하는 모든 사용자의 액세스 정보를 아마존 S3에 보관해 관리

## 트래픽 분산과 오토 스케일 설정

!KakaoTalk_20260731_151409218_03.jpg

- 오토스케일링을 생성해 각 AZ에 EC2 인스턴스에 적절하게 부하 분산을 하도록 실시
- 상황에 따라 적절하게 스케일 작업을 수행하도록

## 데이터베이스 고가용성

!KakaoTalk_20260731_151409218_04.jpg

- RDS for MySQL을 단일 AZ에서 다중 AZ로 변경
- 원본 데이터베이스를 다른 AZ를 복제하고, 원본 데이터베이스에서 가동 중지 혹은 장애가 발생했을 때 복제된 데이터베이스가 마스터 데이터베이스로 승격되어 서비스를 계속해서 운영할 수 있다.
