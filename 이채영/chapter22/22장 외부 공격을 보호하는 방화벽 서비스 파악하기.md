# 외부 공격을 보호하는 방화벽 서비스, AWS WAF 살펴보기

()

> 사용자가 애플리케이션 로드 밸런서를 통해 웹 애플리케이션으로 접근하고자 할 때
>
1. 사용자는 웹 애플리케이션을 가동하는 EC2 인스턴스에 접근하려면 로드 밸런서를 통해 접근을 시도
- 이때 로드 밸런서의 보안 그룹은 허용하는 요청인지 판단하고, 허용하지 않는다면 요청 거부
1. 반대로 허용하는 요청이면 AWS WAF에서 해당 요청이 악의적인 공격인지 검토 실시
2. 모든 요청 및 대응에 대해서는 아마존 클라우드워치를 통해 로깅되며, 아마존  S3에 로그 보존해 관리
3. AWS WAF 검토 결과 문제가 없다면 웹 애플리케이션으로 정상적으로 요청 보내기 가능

()

> 아마존 클라우드프론트를 사용하는 경우
>
1. 아마존 클라우드프론트가 OAI로 아마존 S3 설정
2. 아마존 클라우드프론트에 AWS WAF를 설정해 특정 IP로부터 접근을 차단하거나 허용할 수 있으며, 외부 공격을 탐지하고 방어할 수 있다.
3. 로드 밸런서와 아마존 클라우드프론트를 이용해 웹 애플리케이션을 운용하는 환경이라면
4. 아마존 클라우드 프론트에만 AWS WAF를 설정하거나
5. 두 서비스 모두에 AWS WAF를 설정해 보안을 강화할 수 있다.

## AWS WAF의 주요 5가지 기능

- AWS WAF는 악의적인 공격을 어떻게 판단하고 탐지할까?
    - 애플리케이션에 대한 공격 방어 : IP 주소, HTTP 헤더, 통신 요청 본문, 사용자 지정 URI 등의 기준에 따라 애플리케이션에 대한 통신을 필터링하는 규칙 생성
    - IP 제한으로 인한 무단 액세스 차단 : 의심스러운 또는 악의적인 IP 주소로부터의 통신을 미리 차단
    - DDoS 공격 대책 : 일정 시간 내에 액세스 횟수가 요율 기준 규칙에 설정된 임곗값을 초과하면 해당 IP 주소에서의 액세스를 일시적으로 제한
    - 악의적인 봇 대책 : 스크레이퍼, 스캐너, 크롤러와 같은 일반적인 봇을 쉽게 모니터링하고 검색 엔진 봇을 비롯한 정상적인 봇 액세스만 허용하도록 설정
    - 계정의 무단 로그인 방지 : 애플리케이션의 로그인 페이지를 모니터링하고 도난당한 자격증명으로 로그인 여부 확인

## AWS WAF의 관리형 규칙

- AWS WAF에서는 사용자에게 관리형 규칙을 제공하고 있으며, 이 관리형 규칙을 설정해 방어하고자 하는 특정 유형의 악의적인 트래픽을 필터링하고 차단할 수 있다.

()

- 관리형 규칙 : AWS에서 제공하는 규칙 집합
    - 사용자는 직접 규칙을 만드는 복잡한 과정을 생략할 수 있다.

| 규칙명 | 용도 | 용량 | 비고 |
| --- | --- | --- | --- |
| Admin protection | 외부 액세스를 차단하고 관리 페이지를 보호하는 규칙 | 100 | 환경에 따라 선택 |
| Amazon IP reputation list | 아마존 내부 위협 인텔리전스를 기반으로 만든 규칙 | 25 | **필수로 도입 권장** |
| Anonymous IP list | IP 주소, 사용자의 신원을 난독화할 수 있는 서비스를 사용해 액세스를 차단할 수 있는 규칙 | 50 | 환경에 따라 선택 |
| Core rule set | 일반 웹 애플리케이션에 적용하는 규칙 | 700 | **필수로 도입 권장** |
| Known bad inputs | 무단 액세스 및 취약성 악용과 관련된 입력 패턴을 차단하는 규칙 | 200 | **필수로 도입 권장** |
| Linux operating system | 리눅스 취약점과 관련된 공격을 방지하는 규칙 | 200 | OS에 맞추어 선택 |
| PHP application | PHP 함수를 악용하는 무단 액세스 또는 PHP의 취약성을 찌르는 공격을 차단하는 규칙 | 100 | 환경에 따라 선택 |
| POSIX operating system | POSIX 및 POSIX 호환 운영체제 취약점과 관련된 공격을 방어하는 규칙 | 100 | OS에 맞추어 선택 |
| SQL database | SQL 데이터베이스의 악용을 방지하는 규칙 | 200 | **필수로 도입 권장** |
| Windows operating system | 윈도우 취약점 악용을 방지하는 규칙 | 200 | OS에 맞추어 선택 |
| WordPress application | 워드프레스 취약점을 악용하는 무단 액세스를 차단하는 규칙 | 100 | 환경에 따라 선택 |
- [필수로 도입 권장]은 기본적으로 선택
- AWS WAF의 경우 기본 요금은 용량 1500 WCU를 설정한 요금이 청구되며, 1500 WCU를 초과하는 용량에 대해서는 추가 요금 청구
- WCU : 웹 ACL 용량 단위 (web ACL capacity units)

## AWS WAF의 커스텀 규칙

()

- IP 세트 : 특정 IP의 요청에 대한 허용 또는 차단과 같은 액션을 취할 수 있다.
- 규칙 빌더 : 규칙을 작성할 수 있으며, 여러 조건을 연결하는 AND, OR 선택
    - 헤더, 국가, IP와 같은 검사 필드를 선택하거나 XSS, SQL 인젝션과 같은 조건을 선택해 규칙 하나를 생성할 수 있다.
- 규칙 그룹 : 작성한 규칙을 담을 수 있는 독자적인 규칙 그룹

## 아마존 클라우드프론트에 AWS WAF 도입해보기

> WAF.yml → CloudFront.yml 순서로 클라우드포메이션 스택을 생성해야 한다.
>

https://github.com/classmethodjaewook/aws-developer/tree/main/chapter22

1. AWS WAF 생성하는 리소스를 정의

```yaml
# WAF.yml - WAF 리소스 생성

  WebACL:
    Type: AWS::WAFv2::WebACL # AWS WAF 생성
    Properties:
      DefaultAction: # 규칙에 해당하는 항목이 없을 경우 요청을 허용할지 거부할지 선택
        Allow: {}
      Scope: CLOUDFRONT # 아마존 클라우드프론트에 AWS WAF 도입
      Description: WebACL
      Name: !Sub ${SystemName}-${EnvName}-ACL01
      VisibilityConfig: # 클라우드워치 메트릭을 활성화하고, 샘플링된 요청 정보 모니터링 (샘플링: AWS WAF가 필터링하는 웹 요청 중 일부를 선택해 자세히 분석)
        CloudWatchMetricsEnabled: true
        MetricName: !Sub ${SystemName}-${EnvName}-WebACLMetrics
        SampledRequestsEnabled: true
```

1. AWS WAF 관리형 규칙 추가

```yaml
# WAF.yml - WAF 관리형 규칙 추가

      Rules: # AWS WAF에 관리형 규칙 추가
        - Name: AWS-AWSManagedRulesAmazonIpReputationList
          Priority: 0 # 규칙의 우선순위 설정
          OverrideAction:
            Count: {} # 허용 또는 차단에 대한 규칙 무효호ㅓㅏ하고 해당 요청이 몇 번 발생하는지 카운트
          Statement:
            ManagedRuleGroupStatement:
              VendorName: AWS
              Name: AWSManagedRulesAmazonIpReputationList
          VisibilityConfig:
            CloudWatchMetricsEnabled: true
            MetricName: AWSManagedRulesAmazonIpReputationList
            SampledRequestsEnabled: true
```

1. AWS WAF 로그를 저장할 아마존 S3 버킷을 생성하고 연동

```yaml
# WAF.yml - WAF 로그를 저장할 아마존 S3 연동

  WAFLoggingConfiguration:
    Type: 'AWS::WAFv2::LoggingConfiguration' # AWS WAF의 로그 저장소 지정
    Properties:
      ResourceArn: !GetAtt WebACL.Arn # AWS WAF의 Arn 지정
      LogDestinationConfigs: # 로그를 저장할 리소스의 Arn 지정
        - !GetAtt WAFLogBucket.Arn
```
