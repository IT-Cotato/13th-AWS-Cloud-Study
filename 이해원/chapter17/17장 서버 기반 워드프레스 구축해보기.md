# 17장. 서버 기반 워드프레스 구축해보기

# 1. 서버 기반 워드프레스 구성도 이해하기

워드프레스를 활용한 블로그 플랫폼사이트를 구축해보자.

## 인프라 구성 특징

- 보안성: 프라이빗 서브넷 활용 → 데이터 보호
- 성능: ALB를 통한 부하 분산
- 확장성: 트래픽 증가에 대비한 구조

## 구성도

1. 퍼블릿 서브넷에는 NAT 게이트웨이를 배치해 관리자가 SSM을 통해 EC2 인스턴스로 접속할 수 있게 한다.
2. EC2 인스턴스는 프라이빗 서브넷에 배치해 관리자 이 외에는 접속이 불가능하도록 설정한다.
3. 사용자는 퍼블릭 서브넷에 생성된 로드 밸런서를 이용해 워드프레스에 접근할 수 있다.
4. RDS가 생성된 프라이빗 서브넷에는 NAT 게이트웨이, 인터넷 게이트웨이와 통하는 경로가 없고, EC2 인스턴스와만 상호작용할 수 있다.
    - 관리자는 RDS에 직접 접근이 불가하므로 EC2 인스턴스를 경유해 접근해야 한다.

# 6. 워드프레스에서 추가적으로 고려할 수 있는 사항들

## 6.1 도메인과 고속 콘텐츠 제공

1. 아마존 라우트53 이용
    - 현재  DNS 이름을 사용해 워드 프레스로 접근하고 있으므로, 사용자가 알아보기 쉽게 도메인으로 전환
2. 아마존 클라우드프론트 이용
    - 해외 사용자도 있다면 고속 콘텐츠를 제공할 필요가 있음

## 6.2 HTTPS와 로그 설정

1. HTTPS 설정
    1. 라우트53에 도메인 등록
    2. AWS ACM을 이용해 인증서 발급
    3. 인증서를 로드 밸런서에 등록
2. 로드 밸런서에 액세스 로그 설정
    
    → 로드 밸런서를 통해 접근하는 모든 사용자의 액세스 정보를 S3에 보관해 관리
    

## 6.3 트래픽 분산과 오토 스케일 설정

한 대의 EC2 인스턴스만 가동되고 있으므로 트래픽이 초과해 서버가 다운될 가능성이 있다.

적절하게 트래픽을 분산하고 자동으로 스케일할 필요가 있다.

1. 오토스케일링 생성 → 각 AZ에 EC2 인스턴스에 적절하게 부하 분산
    - 오토스케일링 설정을 통해 상황에 따라 스케일 작업 수행하도록 설정

## 6.4 데이터베이스 고가용성

1. RDS for MySQL을 단일 AZ에서 다중 AZ로 변경
    
    ⇒ 원본 데이터베이스를 다른 AZ에 복제하고, 원본 데이터베이스에 가동 중지/장애 발생 시 복제된 데이터베이스가 마스터 데이터베이스로 승격되어 서비스를 계속 운영할 수 있다.
