# 6장. 객체 스토리지 서비스 파악하기

# 1. 객체 스토리지 서비스, 아마존 S3란?

객체라고 하는 일정한 형태나 형식, 틀이 정해지지 않은 비정형 형식의 데이터를 저장하고 관리하는 스토리지

- S3는 버킷이라는 스토리지에 객체 저장
    - 버킷은 전 리전에 걸쳐 고유한 이름을 가짐
    - 객체는 버킷 내부에서 고유한 키를 가짐
        - 같은 이름의 키 객체 저장 시 덮어쓰기
- S3에 하나의 버킷 내 저장 용량 및 객체 수는 무제한
    - 버킷은 계정당 최대 100개
    - 관리 콘솔 환경에서 버킷으로 객체를 저장한다면 160GB까지만 가능
- S3 버킷에 저장한 객체는 다양한 용도로 활용
    - EC2, RDS와의 연동을 통한 객체 업로드 및 다운로드
    - 서버 로그 저장
    - 서버의 백업을 S3 버킷에 저장
    - presigned URL을 이용해 사용자에게 공유

# 2. 객체 스토리지 서비스, 아마존 S3 살펴보기

## 2.1 스토리지 클래스

S3에서는 다양한 스토리지 클래스를 제공하며,  객체의 GET, PUT, POST, LIST, COPY 등의 요청 수에 따른 요금이 발생한다.

### 스토리지 클래스 종류

- S3 Standard
    - 범용
    - 동적 웹사이트, 콘텐츠 배포, 모바일 및 게임 애플리케이션, 빅데이터 분석 등
- S3 Infrequent Access
    - 액세스 빈도가 낮은 객체를 위한 스토리지 클래스
    - 백업, 재해 대책 파일 등
- S3 One Zone-IA
    - 액세스 빈도가 낮은 객체를 위한 스토리지 클래스
    - 로그, 자주 액세스하지 않는 데이터의 재생성 등
- S3 Glacier Instant Retrieval
    - S3 Infrequent Access와 비교해 액세스 빈도가 낮음
    - 의료 이미지, 미디어 자산 등
- S3 Glacier Flexible Retrieval
    - S3 Infrequent Access와 비교해 액세스 빈도가 낮음
    - 백업, 재해 복구 사용 사례
- S3 Glacier Deep Archive
    - 규제 규정 준수 요건을 충족하기 위해 7~10년 이상 보관할 필요가 있는 객체, 백업, 재해 복구 사용 사례
- S3 Intelligent-Tiering
    - 액세스 빈도에 따라 스토리지 요금 최적화

### 스토리지 클래스 설정

객체를 업로드할 때나 업로드한 객체를 편집해 스토리지 클래스를 설정할 수 있다. 

- 기본값 : S3 Standard
- 업로드한 객체에서 [작업] → [스토리지 클래스 편집] 클릭해 변경

## 2.2 버전 관리를 위한 버저닝 기능

버저닝을 사용하면 단일 객체의 여러 버전을 유지할 수 있다.

- 버저닝을 설정하지 않은 경우
    - 업로드한 객체는 단일 객체로 저장
    - 삭제나 덮어쓰기 발생 시 객체를 복구하거나 되돌릴 수 없음
- 버저닝 유효화한 경우
    - 객체를 업로드할 때마다 새로운 버전 생성 → 되돌리거나 삭제된 객체복구 가능
    - 새 버전이 만들어지면 사용료 증가
- S3 생성 시 버킷 버전 관리 항목에서 버저닝 활성 유무 선택

## 2.3 생명주기 규칙을 활용한 객체 관리

생명주기를 활성화하면, 객체를 생성한 날로부터 지정한 기간이 경과된 객체를 자동 삭제한다. 

### 생명주기 활용 예시

1. 생명주기는 S3 버킷 내 관리탭에서 확인
    - [생명주기 규칙 생성]을 클릭해 생명 주기 규칙 생성
2. 생명주기 규칙 입력, 규칙 범위 선택
    - [하나 이상의 필터를 사용해 이 규칙의 범위 제한]: 지정된 경로에 규칙 적용
    - [버킷의 모든 객체에 적용]: 버킷 내부의 모든 디렉터리에 규칙 적용
    - [하나 이상의 필터를 사용해 이 규칙의 범위 제한]: 규칙을 적용할 S3 버킷 경로 지정
3. [최소 객체 크기]는 특정 크기 이상의 객체에만 생명주기 규칙이 적용되도록 지정 
    - [최대 객체 크기]: 특정 크기 이하의 객체에만 생명주기 규칙 적용되도록 지정
    - 필수 옵션 X, 지정하지 않아도 됨
4. 생명주기 규칙 작업 선택
    - 특정 기간이 지나면 객체가 삭제/만료되도록 설정하려면 [객체의 현재 버전 만료 체크]
        - 객체 생성 후 경과 일수 입력

# 3. 아마존 S3 생성하기

## 3.1 클라우드포메이션으로 S3 생성하기

- S3.yml
    
    ```yaml
    AWSTemplateFormatVersion: "2010-09-09"
    Description: Create S3
    # ------------------------------------------------------------
    # Input Parameters
    # ------------------------------------------------------------
    Parameters:
      SystemName:
        Description: "System name of each resource names."
        Type: String
        Default: "gr"
      EnvName:
        Description: "Environment name of each resource names."
        Type: String
        Default: "product"
      BucketName:
        Description: "Bucket name."
        Type: String
        Default: "bucket"
    # ------------------------------------------------------------#
    # Create S3 Bucket
    # ------------------------------------------------------------# 
    Resources:
      S3Bucket:
        Type: AWS::S3::Bucket
        Properties:
          # 파라미터를 조합하여 버킷 이름 결정 (예: gr-product-bucket)
          BucketName: !Sub ${SystemName}-${EnvName}-${BucketName}
          
          # [보안 설정] 모든 퍼블릭 액세스를 차단 (보안 베스트 프랙티스)
          PublicAccessBlockConfiguration:
            BlockPublicAcls: true
            BlockPublicPolicy: true
            IgnorePublicAcls: true
            RestrictPublicBuckets: true
            
          # [수명 주기 설정] 90일이 지난 객체는 자동으로 삭제
          LifecycleConfiguration:
            Rules:
              - Id: !Sub ${SystemName}-lifecycle-bucket
                Status: Enabled
                ExpirationInDays: 90
                
          # [태그 설정] 비용 추적 및 리소스 관리를 위한 메타데이터
          Tags:
            - Key: Name
              Value: !Sub ${SystemName}-${EnvName}-${BucketName}
            - Key: Env
              Value: !Sub ${EnvName}
    
    #------------------------------------------------------------
    # Output Parameters: 생성된 리소스 정보를 다른 스택에서 참조할 수 있도록 출력
    #------------------------------------------------------------
    Outputs:
      S3Bucket:
        Value: !Ref S3Bucket
        # Export된 이름은 다른 CloudFormation 스택에서 ImportValue로 가져와 사용 가능
        Export:
          Name: !Sub ${EnvName}-${BucketName}
    ```
