<!--StartFragment--><h1>클라우드 서버 최적화를 위한 백엔드 서비스 파악하기</h1>
<h1>1. 클라우드 서버 최적화, 아마존 EC2 오토스케일링이란?</h1>
<p>오토 스케일링은 스케일업, 스케일아웃, 스케일인을 구현하는 데 사용된다.</p>
<ul>
<li>스케일업
<ul>
<li>서버의 성능 향상을 위해 기존 EC2 인스턴스의 사양 업그레이드</li>
<li>CPU, 메모리, 디스크 용량 등의 리소스를 늘리는 것</li>
</ul>
</li>
<li>스케일아웃
<ul>
<li>시스템 성능 향상을 위해 같은 사양의 추가 서버를 추가</li>
<li>시스템 부하 분산, 가용성 향상</li>
</ul>
</li>
<li>스케일인
<ul>
<li>스케일아웃 목적으로 생성된 서버가 필요 없다면 스케일인을 수행해 서버 삭제</li>
</ul>
</li>
</ul>
<h2>AWS 오토스케일링 VS 아마존 EC2 오토스케일링</h2>
<p>AWS 오토스케일링은 아마존 EC2 오토스케일링을 포함해 아마존 ECS, 다이나모 DB, 아마존 오로라와 같은 다양한 서비스에 대한 스케일링 작업을 수행하는 서비스다.</p>
<p>AWS 서비스에 대한 오토스케일링을 중앙 집중식으로 관리/통합할 수 있다.</p>
<h1>2. 클라우드 서버 최적화 서비스, 아마존 EC2 살펴보기</h1>
<p>EC2 오토스케일링은 오토스케일링 그룹을 생성해 EC2 인스턴스에 대한 스케일업, 스케일아웃, 스케일인을 구현할 수 있다.</p>
<p>오토스케일링 그룹을 생성하려면 EC2 인스턴스 구성을 설정할 필요가 있는데 이때 시작 템플릿을 사용한다.</p>

<h2>2.1 클라우드 서버 최적화 백엔드 서비스, 오토스케일링 그룹이란?</h2>
<h3>오토스케일링 그룹 크기</h3>
<ul>
<li>원하는 용량: 오토스케일링 그룹을 만들 때 생성할 초기 EC2 인스턴스 수</li>
<li>최소 용량: 최소 EC2 인스턴스 수</li>
<li>최대 용량: 최대 EC2 인스턴스 수</li>
</ul>
<p>

<img width="546" height="281" alt="Image" src="https://github.com/user-attachments/assets/ffcf02ba-b118-4033-829d-daab28ebf8fc" />

</p>
<p>최소 용량이 2인 경우 오토스케일링 그룹에 속한 EC2 인스턴스 한 대를 삭제하더라도 최소 용량을 유지하고자 새로운 EC2 인스턴스를 생성해 항상 EC2 인스턴스 두 대를 유지한다.</p>
<h3>오토스케일링 그룹과 로드 밸런서</h3>
<p>확장성과 가용성을 고려해 오토스케일링 그룹과 로드 밸런서를 함께 사용하는 것을 권장한다.</p>
<p>로드 밸런서를 개별적으로 생성 후 연결할 수 있으며, 오토스케일링 그룹을 생성하면서 새 로드 밸런서를 생성해 연결할 수 있다.</p>
<p>오토스케일링 그룹과 연결된 로드 밸런서는 별도로 [탄력적 로드 밸런서 상태 확인 켜기] 기능을 제공한다.</p>
<ul>
<li>EC2 인스턴스에서 unhealthy 발생 → EC2 인스턴스를 오토스케일링 그룹에서 제외 → 새로운 EC2 인스턴스 가동 후 그룹에 추가</li>
</ul>

<h3>오토스케일링 그룹과 AMI</h3>
<p>오토스케일링 그룹을 생성할 때 설정한 값을 바탕으로 EC2 인스턴스가 생성되므로 사용자가 수동으로 설치한 소프트웨어는 스케일 작업을 통해 생성된 EC2 인스턴스에는 적용되지 않는다.</p>
<p>⇒ AMI 교체</p>
<ol>
<li>오토스케일링 그룹으로 생성된 EC2 인스턴스에 소프트웨어 설치</li>
<li>EC2 인스턴스의 AMI 생성, AMI 기반으로 새로운 EC2 인스턴스 생성</li>
</ol>
<blockquote>
<p>AWS에서는 워드프레스가 설치된 AMI, MySQL이 설치된 AMI 등 미리 소프트웨어가 설치된 AMI를 배포하고 있다.</p>
</blockquote>
<h3>오토스케일링 그룹 종료 정책</h3>

| 종료 정책 | 작업 | 비고 |
| :--- | :--- | :--- |
| **기본값** | • 순서대로 조건에 일치하는 EC2 인스턴스를 찾아냄<br>• 가용 영역내에서 종료 방지 기능이 설정되지 않은 EC2 인스턴스 삭제<br>• 가장 오래된 시작 템플릿이 있는 인스턴스 삭제<br>• 여러 대 존재할 경우 결제 시간이 가장 가까운 인스턴스 삭제 | |
| **할당 전략** | 인스턴스의 유형(스팟 인스턴스 혹은 온디맨드 인스턴스)의 배포 전략에 맞춤 | |
| **가장 오래된 시작 템플릿** | 가장 오래된 시작 템플릿을 사용하는 인스턴스 삭제 | |
| **가장 오래된 시작 구성** | 가장 오래된 시작 설정을 가진 인스턴스 삭제 | 오래된 버전의 AMI, 인스턴스 유형, 보안 그룹 등 포함 |
| **다음 인스턴스 시간과 가장 가까움** | 결제 시간에 가장 가까운 인스턴스 삭제 | |
| **최신 인스턴스** | 오토스케일링 그룹 내 가장 최근 생성된 인스턴스 삭제 | |
| **가장 오래된 인스턴스** | 오토스케일링 그룹 내 생성 시간이 가장 오래된 인스턴스 삭제 | |

    Type: String

    Type: AWS::EC2::KeyPair
    Properties:
      KeyName: !Ref KeyPairName

  WebLaunchTemplate:
    Type: AWS::EC2::LaunchTemplate # 시작 템플릿 생성
    Properties:
      LaunchTemplateName: !Sub ${SystemName}-${EnvName}-AppLaunchConfiguration
      LaunchTemplateData:
        # 다른 스택(네트워크/IAM)에서 정의한 값을 가져와 연결 (결합도 관리)
        IamInstanceProfile:
          Arn:
            Fn::ImportValue: !Sub ${EnvName}-ec2-role-arn
        BlockDeviceMappings: 
        - DeviceName: /dev/sda1
          Ebs:
            VolumeType: gp3 # 볼륨 유형
            VolumeSize: 100 # 볼륨 크기
            DeleteOnTermination: true
            Encrypted: true
        NetworkInterfaces: 
        - AssociatePublicIpAddress: true
          DeviceIndex: 0
          Groups:
            - Fn::ImportValue: !Sub ${EnvName}-ec2-sg
        ImageId: !Ref EC2AMI
        InstanceType: !Ref InstanceType
        KeyName: !Ref KeyPairName
        # 인스턴스 생성 시 자동 실행될 스크립트 (프로비저닝의 자동화)
        # EC2 인스턴스의 사용자 데이터를 사용해 아파치 서버 설치
        # 스케일 작업으로 EC2 인스턴스가 생성될 때 아파치가 설치된 인스턴스 생성
        UserData: !Base64 | 
          #!/bin/bash
          sudo yum update -y
          sudo yum install httpd-2.4.51 -y
          sudo systemctl start httpd
          sudo systemctl enable httpd
          sudo httpd -v
          sudo cp /usr/share/httpd/noindex/index.html /var/www/html/index.html

# ------------------------------------------------------------#

      # 최신 버전의 템플릿을 참조하도록 설정
      LaunchTemplate:
        LaunchTemplateId: !Ref WebLaunchTemplate
        Version: !GetAtt WebLaunchTemplate.LatestVersionNumber
      MetricsCollection: # 오토스케일링 그룹에서 집계된 데이터를 클라우드워치로 보낼 설정값 지정

          Metrics: # 어떤 데이터를 집계해보낼지 설정
            - GroupMinSize 
            - GroupMaxSize
      # 운영 핵심: 인스턴스의 상태 체크 방식 (EC2 기반 또는 ELB 기반 선택 가능)

      # 가용성 핵심: 최소/최대/희망 인스턴스 수 정의
      MaxSize: '3'
      MinSize: '2'
      DesiredCapacity: '2'
