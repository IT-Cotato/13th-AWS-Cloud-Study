# 21장. 모니터링 및 로깅 서비스 파악하기

# 1. 모니터링 및 로깅 서비스, 아마존 클라우드워치란?

아마존 클라우드워치는 실시간으로 모니터링을 수행하며, 로그, 메트릭, 이벤트를 통해 모니터링 및 운영 데이터를 수집한다.

# 2. 아마존 클라우드워치 살펴보기

메트릭 = 클라우드워치 매트릭

- 매트릭: 지표 →  EC2나 RDS와 같은 감시 대상으로부터 취득하는 데이터를 정리해놓은 것
    - 표준 지표, 맞춤형 지표

## 2.1 모니터링 및 로깅을 위한 서비스, 메트릭

- 표준 지표: AWS 내에서 관리할 수 있는 범위의 정보
- 맞춤형 지표: 표준 지표로 수집되지 않은 정보를 수집할 때 사용자가 직접 커스텀해 지표를 만듦
    - EC2 인스턴스의 표준 지표에는 디스크 사용률, 메모리, OS 이상의 정보는 수집하지 않으므로 맞춤형 지표를 이용해 수집

## 2.2 모니터링 및 로깅 서비스, 경보

매번 콘솔 화면으로 들어가 확인 절차를 거치는 것은 번거롭기 때문에 AWS에서는 클라우드워치 경보 서비스를 제공한다.

아마존 SNS를 통해 관리자에게 알림을 보내도록 설정할 수 있다.

## 2.3 모니터링 및 로깅 서비스, 로그

아마존 클라우드워치에서는 시스템, 애플리케이션, AWS 서비스의 로그를 중앙에서 관리하는 로그 그룹을 제공한다.

사용자는 이런 로그 그룹을 통해 특정 오류 코드를 확인하고, 트러블슈팅과 분석을 수행할 수 있다.

1. 클라우드워치 콘솔 화면의 [로그 그룹] → 리스트 확인
2. 로그 그룹 리스트 중 하나를 클릭하면 [로그 스트림]에서 보존된 로그 확인 가능

로그 그룹은 요금이 발생하는데, 아마존 S3와 동일하게 클래스를 선택할 수 있다.

- Standard: USD 0.76
- Infrequent Access: USD 0.38

보존 설정으로 일정 시간이 지나면 로그를 자동으로 삭제할 수 있다.

## 2.4 모니터링 및 로깅을 위한 서비스, 메트릭을 취득할 수 있는 서비스

- CloudWatch_Alarms.yml
    - `ComparisonOperator` 옵션 → 임곗값 지정
    
    ```yaml
    AWSTemplateFormatVersion: "2010-09-09"
    Description: Create CloudWatch Alarms
    # ------------------------------------------------------------#
    # Input Parameters
    # ------------------------------------------------------------# 
    Parameters:
      SystemName:
        Description: "System name of each resource names."
        Type: String
        Default: "gr"
      EnvName:
        Description: "Environment name of each resource names."
        Type: String
        Default: "product"
      Ec2InstanceId:
        Description: Ec2 InstanceId
        Type: AWS::EC2::Instance::Id
    
    # ------------------------------------------------------------#
    #  Create CloudWatch Alarms
    # ------------------------------------------------------------#
    Resources:
      C2CPUUtilizationAlarm:
        Type: AWS::CloudWatch::Alarm
        Properties:
          AlarmActions:
            - Fn::ImportValue: !Sub ${EnvName}-sns
          AlarmName: !Sub ${SystemName}-${EnvName}-Alarms
          MetricName: CPUUtilization
          Namespace: AWS/EC2
          Statistic: Average
          Period: 60
          EvaluationPeriods: 2
          Threshold: 40
          TreatMissingData: breaching
          OKActions: 
            - Fn::ImportValue: !Sub ${EnvName}-sns
          ComparisonOperator: GreaterThanOrEqualToThreshold
          Dimensions:
            - Name: InstanceId
              Value: !Ref Ec2InstanceId
    ```
    

1. 클라우드포메이션 스택 생성
    1. CloudWatch_Alarms.yml에서는 모니터링해 경보를 발생시킬 EC2 인스턴스 선택
2. 생성한 아마존 SNS 토픽 확인
    1. 아마존 SNS 콘솔 화면 [구독] 진입
    2. 상태가 [확인됨]으로 표시되는지 확인
3. 아마존 클라우드워치 콘솔 화면에서 경보 확인
    1. [모든 경보]에서 생성된 경보 확인
4. 경보가 발생하면 지정한 아마존 클라우드워치의 [경보 상태]를 클릭해 확인 
    - 경보가 발생하지 않는다면 stress를 사용해 강제로 CPU 사용률을 높여 경보를 받을 수 있음
        
        ```bash
        sudo amazon-linux-extras install epel -y
        sudo yum install stress -y
        sudo stress --cpu 1 --timeout 600
        ```
