<!--StartFragment--><h1>13장. 컨테이너를 위한 백엔드 서비스 파악하기</h1>
<h1>1. 컨테이너 서비스, 아마존 ECS란?</h1>
<p>ECS(Elastic Container Service)는 AWS에서 도커 컨테이너를 배포하고 운영, 관리하는 완전 관리형 컨테이너 서비스이다.</p>
<h2>도커</h2>
<p>도커는 다른 컴퓨터에서도 같은 개발 환경을 구성할 수 있도록 하여 환경 불일치를 해결한다.</p>
<h3>도커파일</h3>
<pre><code class="language-docker"># 베이스 이미지 지정 (Nginx 최신 안정버전 사용)
FROM nginx:alpine
# 도커파일 작성자/관리자 정보 지정
MAINTAINER YourName &lt;your_email@example.com&gt;
# 호스트의 웹 콘텐츠 파일들을 컨테이너의 Nginx 기본 웹 디렉터리로 복사
COPY ./html /user/share/nginx/html
# 컨테이너가 외부와 통신할 기본 웹 포트(80) 지정
EXPOSE 80
# 컨테이너가 시작될 때 Nginx 서버를 백그라운드가 아닌 포그라운드로 실행
# (컨테이너가 종료되지 않고 계속 유지되도록 만든다.)
CMD [&quot;nginx&quot;, &quot;-g&quot;, &quot;daemon off;&quot;]
</code></pre>
<ul>
<li><code>FROM</code> : 베이스 이미지 지정
<ul>
<li>
<p>lastest vs alpine</p>
<p>가장 큰 차이는 &quot;이미지의 크기(용량)&quot;와 &quot;보안 및 경량화&quot;에 있다.
<code>nginx:latest</code>는 데비안(Debian) 리눅스를 기반으로 만들어진 표준 이미지이고, <code>nginx:alpine</code>은 알파인(Alpine) 리눅스라는 초경량 리눅스를 기반으로 만든 이미지이다.</p>

항목 | nginx:latest (교재 가이드) | nginx:alpine (실무 추천)
-- | -- | --
기반 OS | 데비안 리눅스 (Debian) | 알파인 리눅스 (Alpine)
이미지 크기 | 약 140MB ~ 190MB (무거움) | 약 20MB ~ 30MB (매우 가벼움)
포함된 도구 | bash, curl, apt 등 웬만한 툴 내장 | sh, apk 등 최소한의 필수 도구만 내장
보안성 | 포함된 패키지가 많아 취약점 노출 확률 상대적 높음 | 코드가 최소화되어 있어 공격 표면(Attack Surface)이 좁음


</li>
</ul>
</li>
<li><code>MAINTAINER</code> : 도커파일의 작성자/수정한 사람 이름 지정</li>
<li><code>COPY</code> : 호스트 파일을 지정된 디렉터리에 복사</li>
<li><code>EXPOSE</code> : 컨테이너가 노출할 포트 지정</li>
<li><code>CMD</code> : 컨테이너가 시작될 때 실행될 기본 명령 지정</li>
</ul>

<p>ECS는 정적인 이미지를 보관하는 ECR(Elastic Container Registry) 서비스를 제공한다.</p>

<img width="747" height="342" alt="Image" src="https://github.com/user-attachments/assets/a6af3da5-fe1a-4ef5-985a-98727bca9df2" />

<ol>

<h2>2.2 컨테이너 서비스, 아마존 ECS 구성 요소</h2>
<p>ECR에 푸시한 정적인 이미지를 동적인 이미지로 변환해 하나의 컨테이너로 사용하기 위해 ECS를 사용한다.</p>
<h3>ECS 작업 정의</h3>
<p>ECR의 리포지터리에 생성한 정적 이미지를 사용하려면 ECS에 작업 정의를 작성해야 한다.</p>
<p>작업 정의는 컨테이너의 전체적인 구성을 정의하는 것으로, 어떤 컨테이너를 만들 것인지 설정하는 작업이다.</p>
<ul>
<li>작업 이름, 컨테이너 이름, 사용할 이미지, 사용할 포트 번호, 환경 변수 설정, 컨테이너에 연결할 볼륨, 실행 역할, 네트워크 모드
<ul>
<li>네트워크 모드는 호스트/브리지/awsvpc/없음 모드 중 선택</li>
</ul>
</li>
</ul>
<h3>호스트 모드</h3>
<p>호스트의 ENI(Elastic network interface)를 사용해 컨테이너가 통신하는 모드</p>
<p>호스트 모드는 호스트에서 사용하는 포트가 컨테이너 포트가 된다.</p>
<p>ENI를 나눠서 컨테이너를 구성한다면 같은 포트를 사용해도 괜찮지만 같은 ENI를 사용하게 되면 문제가 발생한다.</p>
<blockquote>
<p>ENI는 가상 네트워크 인터페이스이며, 생성한 리소스에 연결되어 IP 주소를 부여한다.</p>
</blockquote>
<p>

<img width="747" height="591" alt="Image" src="https://github.com/user-attachments/assets/b36f34e0-885a-4602-8ac9-8d8b6851d8fa" />

</p>
<p>호스트 모드에서는 부하 분산 구현이 불가능하다.</p>
<p>호스트 모드에서는 컨테이너의 네트워크 네임스페이스가 호스트의 네트워크 네임스페이스와 공유되므로 컨테이너의 포트가 호스트의 포트로 직접 매핑된다.</p>
<p>이런 구성에서는 하나의 포트 번호만 사용 가능하며, 로드 밸런서를 통한 컨테이너간 부하 분산이 불가능하다.</p>
<h3>브리지 모드</h3>
<p>

<img width="639" height="477" alt="Image" src="https://github.com/user-attachments/assets/e7a0ec69-9197-4c6e-b4ed-5ac7a5d391f4" />

<p>ENI와 컨테이너 사이에 브리지 레이어를 추가해, 호스트와 컨테이너를 다른 포트로 연결할 수 있다.</p>
<p>

<img width="726" height="409" alt="Image" src="https://github.com/user-attachments/assets/69310c08-f8a1-4a46-a2e3-80a24d329290" />

</p>
<p>같은 포트로 여러 컨테이너를 가동시킬 수 있다.</p>
<p>호스트 포트는 브리지의 동적 매핑 기능에 의해 호스트 포트와 컨테이너 포트를 별도로 지정할 수 있다.</p>
<p>호스트 포트를 0으로 지정하면 컨테이너 인스턴스의 임시 포트 범위(32768~61000)에서 호스트 포트가 동적으로 매핑된다. → 임시 포트 범위를 에페메랄 포드라고 한다.</p>
<p>포트를 무작위로 할당하면 포트 제어가 어려우므로 주의해야 한다.</p>
<h3>awsvpc 모드</h3>
<p>각 컨테이너마다 ENI를 생성해 대응하는 모드이다.</p>
<p>생성된 ENI는 호스트와는 별도로 생성되며, VPC 내에서 자체 사설 IP가 할당된다.</p>
<p>더 유연한 설정이 가능한 모드이다. 단점은 생성할 수 있는 ENI 수에 제한이 있다는 점이다.</p>
<h3>없음 모드</h3>
<p>포트 매핑이 불가능하며, 외부와의 연결도 차단된 모드이다.</p>
<p>로그 수집, 데이터 교환, 데이터베이스 등 네트워크 기능이 불필요할 때 사용하는 모드이다.</p>
<h3>ECS 작업</h3>
<p>생성할 컨테이너를 설정했다면 작업을 통해 이런 설정을 적용하고 컨테이너를 실행할 수 있다.</p>
<p>단일 작업 내에서 여러 컨테이너를 시작할 수 있으며, 엔직엔스와 마리아DB와 같은 서비스를 하나의 작업 내에서 실행시킬 수 있다.</p>
<h3>ECS 서비스</h3>
<p>서비스는 작업을 관리한다. 작업 중 하나가 실패/중지되는 경우 서비스에서 설정한 필요한 작업 수에 따라 자동으로 새 작업이 시작된다.</p>
<p>서비스에서는 컨테이너의 시작 유형을 선택할 수 있다.</p>
<ul>
<li>EC2 인스턴스
<ul>
<li>컴퓨팅 서비스</li>
</ul>
</li>
<li>파게이트
<ul>
<li>컨테이너를 서버리스로 실행 가능하도록 함</li>
<li>사용자는 애플리케이션에만 집중, 운영체제의 관리나 운용 보수 작업 등을 신경 쓰지 않아도 됨</li>
</ul>
</li>
</ul>
<p>서비스에서 컨테이너에서 사용할 보안 그룹과 VPC, 서브넷 등을 선택할 수 있다.</p>
<h3>ECS 클러스터</h3>
<p>클러스터는 서비스와 작업을 포함하는 컨테이너 관리 및 배포를 위한 컴퓨팅 자원의 집합이다.</p>
<p>클러스터는 여러 EC2 인스턴스나 파게이트 작업으로 구성되어 있으며, 이를 통해 여러 서비스 및 작업을 실행/관리할 수 있다.</p>
