# 5장. 관계형 데이터베이스 서비스 파악하기

# 1. 관계형 데이터베이스, 아마존 RDS란?

- Amazon Relational Database Service
- AWS에서 관계형 데이터베이스를 제공하는 서비스
- 관리형 서비스 → 대부분의 작업과 관리를 AWS에서 담당
    - ex) 데이터베이스 백업, 소프트웨어 패치, 장애 감지 및 복구를 자동으로 관리

> 아마존 RDS는 RDS, RDS 인스턴스, DB 인스턴스라고도 부른다.
>

## 2.1. 아마존 RDS 엔진 유형
| 엔진 유형 | 특징 | 비고 |
| :--- | :--- | :--- |
| **Amazon Aurora** | • 클라우드에 최적화된 MySQL 및 PostgreSQL 호환 DB<br>• 표준 MySQL 대비 최대 5배, PostgreSQL 대비 최대 3배 빠른 성능<br>• 자동 확장(Serverless) 및 뛰어난 고가용성 지원 | • AWS에서 가장 권장하는 고성능 옵션<br>• 스토리지 자동 확장(최대 128TB) |
| **MySQL** | • 세계에서 가장 널리 사용되는 오픈 소스 관계형 DB<br>• 방대한 생태계와 레퍼런스 보유<br>• 빠르고 안정적이며 설정이 비교적 간단함 | • 범용적인 웹 및 모바일 애플리케이션에 가장 무난한 선택 |
| **PostgreSQL** | • 강력한 기능을 자랑하는 오픈 소스 객체 관계형 DB<br>• 복잡한 쿼리, JSON 데이터 형식 지원 등 고급 기능 제공<br>• 데이터 무결성과 표준 준수에 강점 | • 복잡한 연산이나 분석, 지리 공간 데이터(PostGIS) 처리에 적합 |
| **MariaDB** | • MySQL을 기반으로 만들어진(Fork) 오픈 소스 DB<br>• MySQL과의 높은 호환성 유지<br>• 커뮤니티 주도로 빠른 신기능 업데이트 및 성능 개선 | • 기존 MySQL 환경을 대체하거나 호환성을 유지하면서 다른 옵션을 찾을 때 유용 |
| **Oracle** | • 세계 최고 수준의 점유율을 가진 엔터프라이즈(상용) DB<br>• 대규모 데이터 처리, 강력한 보안 및 엔터프라이즈급 기능 지원 | • 라이선스 비용 발생<br>• '라이선스 포함(License Included)' 모델과 '기존 라이선스 사용(BYOL)' 모델 중 선택 가능 |
| **Microsoft SQL Server** | • Microsoft에서 개발한 엔터프라이즈(상용) 관계형 DB<br>• .NET 프레임워크 및 Windows 생태계와의 완벽한 통합<br>• 다양한 에디션(Express, Web, Standard, Enterprise) 지원 | • 라이선스 비용 발생<br>• 기존에 Microsoft 기반 인프라를 구축한 기업에 적합 |
| **IBM Db2** | • 미션 크리티컬 워크로드를 위해 설계된 상용 DB<br>• 고성능, 뛰어난 안정성 및 재해 복구 기능 제공 | • 기존 IBM Db2 고객의 클라우드 마이그레이션에 적합<br>• '기존 라이선스 사용(BYOL)' 모델로 제공됨 |

아마존 오로라

- RDS for MySQL, RDS for PostgreSQL보다 높은 성능
    - 3배 또는 5배 높은 초당 SELECT 수, UPDATE 수 제공
- 오로라는 복제된 인스턴스를 추가해도 스토리지 비용에 영향을 주지 않음
    - 스토리지 관점에서 오로라를 더 저렴하게 이용 가능
    
    → 스토리지 용량이 많을수록, RDS보다는 오로라를 더 저렴하게 활용 가능
    

## 2.2. 아마존 RDS의 DB 인스턴스 클래스

사용 가능한 DB 인스턴스 클래스

- **스탠다드**
    - m 유형을 포함한 인스턴스 클래스
        - db.m3, db.m4, db.m5
    - 범용 DB 인스턴스 클래스
- **메모리 최적화**
    - r, x, z 유형을 포함한 인스턴스 클래스
        - db.r4, db.r5, db.r6i, db.x1, db.x2i, db.zld
    - 메모리에서 대용량 데이터 집합을 처리하는 애플리케이션에 최적화된 DB 인스턴스 클래스
- **버스터블**
    - t 유형을 포함한 인스턴스 클래스
        - db.t2, db.t3, db.t4g
        - t 계열의 인스턴스 유형에서는 미리 결정된 CPU 사용률이 정의됨
    - 최대 CPU 사용량까지 버스트 가능한 DB 인스턴스 클래스
    - 버스트 기능을 사용하는 데 CPU 크레딧 필요

## 2.3. 아마존 RDS의 스토리지 유형

- 범용 SSD(gp2, gp3)
    - 비용, 성능 면에서 밸런스가 잡혀 있고 폭 넓게 사용 가능
- 프로비저닝된 IOPS(io1)
    - 낮은 대기 시간과 높은 I/O 성능이 요구되는 데이터베이스에 적합
- 마그네틱
    - 데이터 액세스 빈도가 낮은 상황에서 사용
    - 구세대 유형 → 권장 X

범용 SSD에서 gp2, gp3의 요금이 같다.

- gp3는 400GB 스토리지 용량 초과 시, IOPS 및 처리량을 개별적으로 구성하여 추가 요금 청구됨

## 2.4. 아마존 RDS를 구성하는 DB 그룹

- **서브넷 그룹**
    - 해당 그룹에 속한 서브넷에 RDS가 생성됨
- **파라미터 그룹**
    - DB 엔진의 파라미터 집합
    - 시간(time_zone), 문자 집합 등 관리
- **옵션 그룹**
    - 연결된 데이터베이스의 스냅샷 관리
    - 옵션을 추가해 다른 서비스와 상호작용을 도움

> RDS를 생성할 때, 사용자가 별도로 생성하지 않으면 디폴트로 DB 그룹들이 생성된다.
서브넷 그룹은 디폴트 서브넷 그룹에 모든 서브넷이 속해 있어서, 퍼블릭 서브넷에 RDS를 생성하는 문제가 발생할 수 있으므로 되도록이면 **DB 그룹은 직접 생성하는 것을 권장**한다.
> 

## 2.5. 확장성과 고가용성을 위한 옵션들

아마존 RDS에서는 확장성과 고가용성을 지원하는 **읽기 전용 복제본(Read Replica)**과 **다중 AZ(Availability Zone)** 기능을 지원한다.

### 읽기 전용 복제본

- 데이터베이스의 부하 분산을 위해 생성된 복제본
- 데이터베이스의 내용을 복제하여 데이터의 읽기, 검색 수행

<img width="357" height="306" alt="Image" src="https://github.com/user-attachments/assets/e35c970f-baa6-420a-b0be-ac9dd6a1767d" />

- 마스터(Master 혹은 Primary) : 복제 대상이 되는 원본 데이터베이스
- 마스터를 기준으로 각 가용 영역에 읽기 전용 복제본 생성
    - 읽기 작업 분산 → 시스템 전체 성능 향상
    - 고가용성도 실현
- 읽기 전용 복제본의 목적은 확장성 향상, 부하 분산이라는 것에 유의해야 한다.

> 아마존 RDS에서는 교차 리전 읽기 전용 복제본를 지원하며, MariaDB, MySQL, 오라클, PostgreSQL, SQL 서버는 다른 리전에 읽기 전용 복제본을 생성하여 재해 복구 능력 향상과 다른 리전으로의 읽기 작업 확장을 지원한다.
> 

### 다중 AZ

<img width="237" height="261" alt="Image" src="https://github.com/user-attachments/assets/6386732e-6aac-4c5a-8c02-e6cf08da9f94" />

- 고가용성을 위해 원본 DB를 다른 AZ로 복제 → 원본 DB의 가동 중지, 장애 발생에 대비
- 원본 DB(마스터) 운영 중단/장애 발생 시, 다중 AZ 구성된 백업 데이터베이스(스텐바이)가 마스터로 승격되어 서비스 운영
    - 스텐바이는 대기 중인 리소스로 읽기, 쓰기 작업은 불가능
- 장애 조치는 자동으로 이루어지며, 약 60~120초 소요
- 높은 가용성, 신뢰성 제공

<img width="364" height="301" alt="Image" src="https://github.com/user-attachments/assets/e128ded4-7d15-4ec5-9692-79bb79c62282" />

PostgreSQL, MySQL에서는 다중 AZ의 기능이 다중 AZ 인스턴스와 다중 AZ 클러스터로 나눠진다.

**다중 AZ 클러스터**

- 읽기, 쓰기가 불가능했던 스텐바이 리소스에서 읽기 기능 지원
- 마스터 장애 발생 시, 2대의 리소스 중 하나가 마스터로 승격 → 읽기, 쓰기 작업 담당
- 제약조건
    - PostgreSQL, MySQL에서만 이용 가능
    - 2대의 읽기 DB 인스턴스만 생성 가능, 추가 인스턴스 생성 불가
    - 스토리지 : 프로비저닝된 IOPS SSD(io1)만 지원
    - 단일 AZ 배포/다중 AZ 배포 중인 인스턴스 ↔ 다중 AZ 클러스터 변경 불가
    
    ⇒ 신중한 검토 필요
    

# 3. 아마존 RDS 구축하기

## 3.1. 클라우드포메이션으로 아마존 RDS 구축하기

<구축할 구성>

<img width="392" height="164" alt="Image" src="https://github.com/user-attachments/assets/a599b711-8c59-4712-88fc-5ac0cd4cda38" />

1. Security_Group.yml에 RDS 보안 그룹 생성에 필요한 리소스 추가
    
    ```yaml
    RDSSecurityGroup:
      Type: AWS::EC2::SecurityGroup
      Properties:
        GroupName: !Sub ${SystemName}-${EnvName}-rds-sg
        GroupDescription: !Sub ${SystemName}-${EnvName}-rds-sg
        # 인바운드(Inbound) 규칙 설정: 외부에서 RDS로 들어오는 트래픽을 제어
        SecurityGroupIngress:
          - IpProtocol: tcp
           # 1521 포트 개방: Oracle 데이터베이스의 기본 포트
            FromPort: 1521
            ToPort: 1521
            # 특정 IP가 아닌 'EC2SecurityGroup'이라는 특정 보안 그룹에서 오는 트래픽만 허용
            SourceSecurityGroupId: !GetAtt EC2SecurityGroup.GroupId 
        # 위치 지정: 이 보안 그룹이 생성될 네트워크 환경(VPC)을 지정
        VpcId:
          Fn::ImportValue: !Sub ${EnvName}-vpc # Cross-Stack 참조: 다른 CloudFormation 스택에서 출력(Export)한 VPC ID 값을 동적으로 가져옴
        Tags:
          - Key: Name
            Value: !Sub ${SystemName}-${EnvName}-rds-sg
          - Key: Env
            Value: !Sub ${EnvName}
    ```
    
2. RDS.yml에 서브넷 그룹 생성에 필요한 리소스 추가
    - RDS는 별도로 서브넷을 그룹화한 서브넷 그룹을 생성하여 관리
    
    ```yaml
    RDSSubnetGroup:
       Type: AWS::RDS::DBSubnetGroup
       Properties:
         DBSubnetGroupName: !Sub ${SystemName}-${EnvName}-dbsub
         DBSubnetGroupDescription: !Sub ${SystemName}-${EnvName}-dbsub Subnet Group
         # RDS가 배치될 네트워크 공간 지정: 고가용성(Multi-AZ) 구성을 위해 최소 2개의 다른 가용 영역(AZ) 서브넷이 필수
         SubnetIds:
           - Fn::ImportValue: !Sub ${EnvName}-datastore-subnet-1a # 다른 스택에서 생성된 AZ '1a'의 데이터스토어 서브넷 ID를 가져옴
           - Fn::ImportValue: !Sub ${EnvName}-datastore-subnet-1b # 다른 스택에서 생성된 AZ '1b'의 데이터스토어 서브넷 ID를 가져옴
    ```
    
3. RDS.yml에서 파라미터 그룹그룹 생성에 필요한 리소스 추가
    - 파라미터 그룹 : 데이터베이스에서 적용되는 파라미터 모음
        - 시간, 날짜와 같은 값 설정
    
    ```yaml
     RDSParameterGroup:
        Type: AWS::RDS::DBParameterGroup # DB 엔진의 세부 설정값(메모리, 커넥션, 타임아웃 등)을 튜닝하고 일괄 적용하기 위한 파라미터 그룹 생성
        Properties:
          DBParameterGroupName: !Sub ${SystemName}-${EnvName}-dbpg19
          Description: !Sub ${SystemName}-${EnvName}-dbpg19 Parameter
          # 이 설정이 적용될 대상 DB 엔진과 버전을 정확히 명시 (Oracle Standard Edition 2, 19c 버전)
          Family: 'oracle-se2-19'
    ```
    
4. RDS.yml에 옵션 그룹 생성에 필요한 리소스 추가
    
    ```yaml
    RDSOptionGroup:
        Type: AWS::RDS::OptionGroup # DB 엔진의 추가 기능(예: Oracle Timezone, 보안/암호화 옵션 등)을 활성화하고 관리하기 위한 옵션 그룹 생성
        Properties:
          OptionGroupName: !Sub ${SystemName}-${EnvName}-dbog19
          OptionGroupDescription: !Sub ${SystemName}-${EnvName}-dbog19 Option Group
          # 옵션 그룹이 적용될 대상 DB 엔진 (Oracle Standard Edition 2)
          EngineName: "oracle-se2"
          # 대상 DB 엔진의 메이저 버전 (19c)
          MajorEngineVersion: "19"
    ```
    
5. RDS.yml에 RDS 생성에 필요한 파라미터 추가
    
    ```yaml
    RDSMasterUserName:
        Description: Staging RDS DB Master User Name.
        Default: "grsys" # DB 최고 관리자(마스터) 계정 ID의 기본값을 'grsys'로 설정
        Type: String
      RDSMasterPassword:
        Description: Staging RDS DB Master Password.
        Type: String
        # 콘솔 화면이나 배포 로그에 비밀번호가 평문으로 노출(Echo)되지 않도록 마스킹(***) 처리하는 필수 보안 설정
        NoEcho: true 
      RDSMaintenanceWindow:
        Description: Staging Enter MaintenanceWindow(UTC)
        Type: String
        # AWS 측의 자동 엔진 패치나 하드웨어 점검이 수행되는 시간대 지정
        # UTC 기준 토요일 18~19시로 설정하여, 서비스 트래픽이 가장 적은 한국 시간(KST) 일요일 새벽 3~4시에 점검이 이루어지도록 유도
        Default: "sat:18:00-sat:19:00" # KST：[日] 03:00 - 04:00
    ```
    
6. RDS.yml에 RDS 생성에 필요한 리소스 추가
    
    ```yaml
      # 실제 데이터베이스(RDS) 인스턴스를 생성하는 리소스
      Type: AWS::RDS::DBInstance
        Properties:
          # AWS 콘솔 화면에 표시될 해당 DB 인스턴스의 고유 식별자(이름)
          DBInstanceIdentifier: !Sub ${SystemName}-${EnvName}-rds
          # 데이터베이스 생성 시 함께 만들어질 초기 데이터베이스 이름 (Oracle의 경우 SID 역할)
          DBName: "grdb" 
          # 한글 데이터의 정상적인 저장 및 처리를 위한 Oracle 전용 캐릭터셋 설정
          CharacterSetName: KO16MSWIN949
          # DB 서버의 컴퓨팅 자원(CPU, 메모리) 크기 지정 (현재 4 vCPU, 16GB RAM 스펙의 t3.xlarge 사용)
          DBInstanceClass: db.t3.xlarge
    ```
    
7. RDS 생성에 필요한 추가 속성 입력
    
    ```yaml
    Properties:
          DBInstanceIdentifier: !Sub ${SystemName}-${EnvName}-rds
          DBName: "grdb"
          CharacterSetName: KO16MSWIN949
          DBInstanceClass: db.t3.xlarge
          Engine: oracle-se2 # Oracle Standard Edition 2 데이터베이스 엔진 사용
          MultiAZ: false # 다중 가용 영역 배포 비활성화 (주로 단일 구성이나 테스트 목적)
          EngineVersion: '19.0.0.0.ru-2023-10.rur-2023-10.r1' # 적용할 Oracle 19c의 특정 패치 버전 명시
          LicenseModel: 'license-included' # AWS가 제공하는 라이선스를 포함하여 사용 (별도 라이선스 구매 불필요)
          Port: 1521 # 통신에 사용할 오라클 기본 포트 번호
          AutoMinorVersionUpgrade: false # 의도치 않은 DB 재시작을 막기 위해 자동 마이너 버전 업데이트 비활성화
          PubliclyAccessible: false # 외부 인터넷에서 DB로 직접 접근하는 것을 차단하여 보안 강화
          AvailabilityZone:
            Fn::Select: 
            - 0
            - Fn::GetAZs: "" # 현재 AWS 리전의 첫 번째 가용 영역(AZ)에 DB 인스턴스를 배치
          StorageType: "gp3" # 비용 대비 성능이 좋은 최신 범용 SSD 스토리지 타입 지정
          AllocatedStorage: "200" # 최초로 할당할 스토리지 용량 (200GB)
          StorageEncrypted: true # 데이터베이스 볼륨의 암호화 활성화
          EnablePerformanceInsights: true # 데이터베이스 부하 분석을 위한 성능 개선 도우미 기능 켜기
          PerformanceInsightsRetentionPeriod: 7 # 성능 분석 데이터 보존 기간을 7일로 설정 (무료 제공 구간)
          BackupRetentionPeriod: 0 # 스냅샷 자동 백업 기능 비활성화 (0으로 설정 시 동작하지 않음)
          MasterUsername: !Ref RDSMasterUserName # 외부 파라미터에서 마스터 관리자 이름 값을 가져옴
          MasterUserPassword: !Ref RDSMasterPassword # 외부 파라미터에서 마스터 관리자 비밀번호 값을 가져옴
          PreferredMaintenanceWindow: !Ref RDSMaintenanceWindow # 외부 파라미터에서 시스템 유지 관리 점검 시간을 가져옴
          VPCSecurityGroups:
            - Fn::ImportValue: !Sub ${EnvName}-rds-sg # 다른 스택에서 생성한 보안 그룹(방화벽 규칙) 적용
          DBSubnetGroupName: !Ref RDSSubnetGroup # DB가 위치할 내부 네트워크 영역 설정
          DBParameterGroupName: !Ref RDSParameterGroup # DB 엔진 세부 설정 튜닝값 적용
          OptionGroupName: !Ref RDSOptionGroup # DB 엔진의 부가 기능 설정 적용
    ```
    

# 4. 아마존 RDS 접속 패턴 살펴보기

## 4.1. EC2 인스턴스를 이용한 RDS 접속

프라이빗 서브넷에 있는 EC2 인스턴스에 오라클 클라이언트를 설치해 RDS로 접속하는 방법

→ EC2 서버에 접속해서 실행

1. wegt 설치
    
    ```bash
    sudo yum install wget
    ```
    
2. Oracle Instant Client 설치 프로그램 다운로드
    
    ```bash
    sudo yum install -y oracle-instantclient19.6-basic-19.6.0.0.0-1.x86_64.rpm
    sudo yum install -y oracle-instantclient19.6-sqlplus-19.6.0.0.0-1.x86_64.rpm
    ```
    
3. Oracle Instant Client 설치
    
    ```bash
    export PATH=/usr/lib/oracle/19.6/client64/bin:$PATH
    export LD_LIBRARY_PATH=/usr/lib/oracle/19.6/client64/bin:$LD_LIBRARY_PATH
    sqlplus64 -v
    ```
    
4. 환경 변수 설정 및 버전 확인 (libnsl 설치)
    
    ```bash
    sudo yum install libnsl
    sqlplus64 -v
    ```
    
5. RDS 엔드포인트, 포트 확인
6. EC2에서 RDS 접근 시도, 비밀번호 입력
    
    ```bash
    sudo sqlplus64 grsys@엔드포인트:1521/grdb
    ```
    

## 4.2. 포트 포워딩을 이용한 RDS 접속

EC2 인스턴스를 대상으로 포트 포워딩 세션을 생성하여 RDS로 접근

1. 파워셸에서 자격증명 호출
    
    ```bash
    aws sts get-caller-identity
    ```
    
2. 포트 포워딩 실시
    
    ```bash
    aws ssm start-session \
    --target 인스턴스ID \
    --document-name AWS-StartPortForwardingSessionToRemoteHost \
    --parameters '{"host":["RDS 엔드포인트"],"portNumber":["1521"],"localPortNumber":["13306"]}'
    ```

Site to Site VPN 또는 다이렉트 커넥트를 통한 접속

Site to Site VPN 또는 다이렉트 커넥트를 도입하는 환경이라면 EC2 인스턴스 경유, 포트 포워딩을 통한 접속보다 간편하고 안전한 접속 방법이다.
