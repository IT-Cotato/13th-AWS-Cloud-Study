# Chapter 21. 모니터링 및 로깅 서비스 파악하기

## 21.1 모니터링 및 로깅 서비스, Amazon CloudWatch란?

Amazon CloudWatch는 EC2, RDS 등 AWS 리소스와 애플리케이션의 상태를 실시간으로 감시하는 모니터링 서비스이다.

CloudWatch는 다음 데이터를 수집하고 시각화한다.

- **메트릭(Metric)**: CPU 사용률, 네트워크 트래픽처럼 시간에 따라 측정되는 수치 데이터이다.
- **로그(Log)**: 시스템과 애플리케이션에서 발생한 기록이다.
- **이벤트(Event)**: 특정 시점에 발생한 상태 변화나 작업 기록이다.

수집한 데이터를 기반으로 현재 시스템 상태를 확인하고, 장애 징후를 조기에 발견하며, 향후 서비스 운영 방향을 결정할 수 있다.

---

## 21.2 Amazon CloudWatch 살펴보기

CloudWatch의 대표 기능은 다음과 같다.

1. AWS 리소스의 메트릭 수집 및 시각화
2. 임계값을 기준으로 한 경보 생성
3. 로그의 수집, 저장 및 검색
4. SNS 등 다른 AWS 서비스와 연동한 알림 전송

---

## 21.2.1 메트릭

메트릭은 AWS 리소스나 애플리케이션의 상태를 나타내는 시계열 데이터이다.

예를 들어 EC2 인스턴스에서는 다음과 같은 메트릭을 확인할 수 있다.

- CPU 사용률
- 네트워크 입력 및 출력
- 디스크 읽기 및 쓰기
- 상태 검사 결과

### 표준 지표

AWS가 기본적으로 제공하고 관리하는 메트릭이다. EC2, RDS 등 서비스마다 수집 가능한 표준 지표가 다르다.

EC2의 표준 지표에서는 CPU 사용률과 네트워크 트래픽 등을 확인할 수 있지만, 메모리 사용량이나 운영체제 내부 정보는 기본적으로 포함되지 않는다.

### 맞춤형 지표

표준 지표로 수집되지 않는 데이터를 사용자가 직접 생성하여 CloudWatch에 전송하는 방식이다.

다음과 같은 정보가 필요할 때 활용한다.

- EC2 메모리 사용률
- 운영체제 내부 상태
- 애플리케이션 고유의 처리량
- 사용자 수나 주문 수처럼 비즈니스에 특화된 수치

## 21.2.2 경보

CloudWatch Alarm은 특정 메트릭이 설정한 조건을 충족했을 때 상태를 변경하고 후속 작업을 수행하는 기능이다.

예를 들어 EC2 CPU 사용률이 일정 수준을 초과하면 다음 흐름으로 알림을 전송할 수 있다.

```
EC2 CPU 메트릭 수집
→ CloudWatch가 임계값과 비교
→ 경보 상태로 변경
→ Amazon SNS 호출
→ 관리자에게 이메일 전송
```

경보를 사용하면 관리자가 매번 AWS 콘솔에 접속하지 않아도 이상 상태를 확인할 수 있다.

### 경보의 주요 구성 요소

- **MetricName**: 감시할 메트릭 이름이다.
- **Namespace**: 메트릭이 속한 AWS 서비스이다.
- **Statistic**: 평균, 합계, 최댓값 등 데이터 계산 방식이다.
- **Period**: 한 번의 평가에 사용할 시간 간격이다.
- **Threshold**: 경보 발생 기준값이다.
- **EvaluationPeriods**: 조건이 몇 번 연속 충족되어야 하는지 나타낸다.
- **ComparisonOperator**: 메트릭과 임계값을 비교하는 방식이다.
- **AlarmActions**: 경보 발생 시 실행할 작업이다.
- **OKActions**: 상태가 정상으로 돌아왔을 때 실행할 작업이다.
- **Dimensions**: 감시할 구체적인 리소스를 지정하는 조건이다.
- **TreatMissingData**: 데이터가 없을 때 이를 어떻게 처리할지 정하는 옵션이다.

### ComparisonOperator 종류

- `GreaterThanOrEqualToThreshold`: 임계값보다 크거나 같음
- `GreaterThanThreshold`: 임계값보다 큼
- `LessThanThreshold`: 임계값보다 작음
- `LessThanOrEqualToThreshold`: 임계값보다 작거나 같음
- `LessThanLowerOrGreaterThanUpperThreshold`: 하한 미만 또는 상한 초과
- `LessThanLowerThreshold`: 하한 미만
- `GreaterThanUpperThreshold`: 상한 초과

## 21.2.3 로그

CloudWatch Logs는 시스템, 애플리케이션, AWS 서비스에서 발생한 로그를 수집하고 관리하는 기능이다.

로그는 다음 구조로 관리된다.

```
로그 그룹(Log Group)
└─ 로그 스트림(Log Stream)
   └─ 개별 로그 이벤트
```

- **로그 그룹**은 같은 목적이나 서비스의 로그를 묶는 단위이다.
- **로그 스트림**은 특정 인스턴스나 애플리케이션에서 연속적으로 발생한 로그의 흐름이다.
- 로그를 검색하여 오류 코드나 장애 원인을 추적할 수 있다.

### 로그 클래스

교재 기준으로 CloudWatch Logs는 다음 두 가지 클래스를 제공한다.

| 로그 클래스 | 특징 | 교재 기준 요금 |
| --- | --- | --- |
| --- | --- | ---: |
| Standard | 자주 조회하는 로그에 적합 | USD 0.76/GB |
| Infrequent Access | 조회 빈도가 낮은 로그에 적합 | USD 0.38/GB |

### 보존 기간

로그 보존 기간을 설정하면 일정 시간이 지난 로그를 자동으로 삭제할 수 있다.

보존 기간은 1일, 1주, 10년 또는 만료 없음 등으로 설정할 수 있으며, 불필요한 로그 저장 비용을 줄이는 데 도움이 된다.

## 21.2.4 메트릭을 취득할 수 있는 서비스

CloudWatch는 EC2와 RDS 외에도 여러 AWS 서비스의 메트릭을 제공한다.

대표적인 대상은 다음과 같다.

- Amazon EC2
- Amazon RDS
- Amazon CloudFront
- AWS Amplify
- AWS AppSync
- Amazon API Gateway
- AWS Batch

서비스마다 제공하는 메트릭이 다르므로, 구축하려는 시스템에서 어떤 데이터를 감시할 수 있는지 사전에 확인해야 한다.

## 21.3 Amazon CloudWatch 활용하기

이 장의 실습에서는 EC2 CPU 사용률이 기준값을 초과했을 때 SNS를 통해 이메일을 전송하는 환경을 구성한다.

### 전체 흐름

```
EC2 인스턴스
→ CPUUtilization 메트릭
→ CloudWatch Alarm
→ SNS Topic
→ 구독자의 이메일
```

CloudFormation 스택은 다음 순서로 생성한다.

```
VPC.yml
→ IAM.yml
→ Security_Group.yml
→ EC2.yml
→ SNS.yml
→ CloudWatch_Alarms.yml
```

---

## 21.3.1 CloudWatch 경보로 이메일 통지하기

### 1. SNS 토픽 생성

이메일 알림을 전송하기 위해 Amazon SNS 토픽을 생성한다.

```yaml
Resources:
  MySNSTopic:
    Type: AWS::SNS::Topic
    Properties:
      TopicName: !Sub ${SystemName}-${EnvName}-sns
      Subscription:
        - Endpoint: 알림을 받을 이메일 주소
          Protocol: email
```

주요 내용은 다음과 같다.

- `AWS::SNS::Topic`으로 SNS 토픽을 생성한다.
- `Endpoint`에 알림을 받을 이메일 주소를 지정한다.
- `Protocol`을 `email`로 설정한다.
- 스택 생성 후 수신한 인증 메일에서 `Confirm subscription`을 눌러야 구독이 활성화된다.
- SNS 콘솔에서 구독 상태가 `확인됨`으로 표시되어야 한다.

### 2. CloudWatch Alarm 생성

```yaml
Resources:
  C2CPUUtilizationAlarm:
    Type: AWS::CloudWatch::Alarm
    Properties:
      AlarmActions:
        - Fn::ImportValue: !Sub ${EnvName}-sns
      OKActions:
        - Fn::ImportValue: !Sub ${EnvName}-sns
      AlarmName: !Sub ${SystemName}-${EnvName}-Alarms
      MetricName: CPUUtilization
      Namespace: AWS/EC2
      Statistic: Average
      Period: 60
      EvaluationPeriods: 2
      Threshold: 40
      TreatMissingData: breaching
      ComparisonOperator: GreaterThanOrEqualToThreshold
      Dimensions:
        - Name: InstanceId
          Value: !Ref Ec2InstanceId
```

### 설정 해석

- EC2의 `CPUUtilization`을 감시한다.
- 60초 동안의 평균 CPU 사용률을 계산한다.
- 평균 사용률이 40% 이상인 상태가 2회 연속 감지되면 경보가 발생한다.
- 경보 발생 시 SNS가 이메일을 전송한다.
- 정상 상태로 복귀했을 때도 SNS 알림을 전송한다.
- `Dimensions`에서 감시할 EC2 인스턴스 ID를 지정한다.
- `TreatMissingData: breaching`은 데이터가 없을 때도 경보 조건을 위반한 것으로 처리하는 설정이다.

### 3. 경보 확인

CloudWatch 콘솔의 **모든 경보** 메뉴에서 생성된 경보의 상태와 조건을 확인한다.

일반적인 상태는 다음과 같다.

- **OK**: 설정한 임계값을 위반하지 않은 상태이다.
- **ALARM**: 임계값을 위반한 상태이다.
- **INSUFFICIENT_DATA**: 평가에 필요한 데이터가 부족한 상태이다.

### 4. CPU 부하 테스트

EC2에 접속하여 `stress` 도구로 CPU 부하를 발생시킬 수 있다.

```bash
sudo amazon-linux-extras install epel -y
sudo yum install stress -y
sudo stress --cpu 1 --timeout 600
```

위 명령은 CPU 한 개를 600초 동안 최대한 사용하도록 한다.

CPU 사용률이 임계값을 넘으면 CloudWatch Alarm이 `ALARM` 상태로 변경되고 SNS를 통해 이메일이 발송된다.

AWS Fault Injection Service를 이용해 부하 상황을 시험하는 방법도 있다.

## Chapter 21 핵심 정리

- CloudWatch는 AWS 리소스와 애플리케이션을 모니터링하는 서비스이다.
- 메트릭은 시간에 따라 변하는 수치 데이터이다.
- 표준 지표에 없는 메모리 사용률 등은 맞춤형 지표로 수집해야 한다.
- CloudWatch Alarm은 메트릭이 임계값을 넘었을 때 상태를 변경하고 후속 작업을 수행한다.
- SNS와 연동하면 경보 내용을 이메일로 전송할 수 있다.
- CloudWatch Logs는 로그 그룹과 로그 스트림 단위로 로그를 관리한다.
- 로그 보존 기간과 로그 클래스를 조정하면 저장 비용을 줄이는 데 도움이 된다.
