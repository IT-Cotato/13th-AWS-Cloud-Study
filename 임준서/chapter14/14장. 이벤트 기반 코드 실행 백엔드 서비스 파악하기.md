## 14.1 이벤트 기반 코드 실행 서비스, AWS 람다란?

AWS 람다는 AWS에서 제공하는 서버리스 서비스로, 서버를 구축하지 않고도 작성한 코드를 실행할 수 있는 이벤트 구동형 프로그램 실행 환경이다. 넓은 의미로 보면 서버리스이고, 더 명확하게 표현하면 **FaaS(Functions-as-a-Service)** 로 표현할 수 있다.

### 서버리스와 FaaS의 관계

- **서버리스**: 다양한 서비스 범주에 중점을 두며, 여기에는 **스토리지, 데이터베이스, 컴퓨팅** 등이 포함된다. 이런 서버리스 환경에는 **FaaS도 포함**된다.
- **FaaS**: 개발자가 직접 개발한 개별 함수를 클라우드에서 실행할 수 있으며, 필요에 따라 다른 함수와 결합해 애플리케이션을 개발할 수 있다. 애플리케이션 개발에 필요한 서버 준비와 관리 시간을 생략할 수 있다는 장점이 있다. 서버리스 아키텍처라고도 하며, 개발자는 특정 이벤트나 요청이 발생할 때 실행되는 함수를 작성하기만 하면 된다. 대표적인 AWS 서비스로 **AWS 람다**가 있다.

### 클라우드 서비스 모델 비교

| 모델 | 설명 | 대표 서비스 |
| --- | --- | --- |
| **IaaS** (Infrastructure as a Service) | 스토리지, 네트워크, 서버와 같은 하드웨어 리소스를 제공. 개발자는 이를 바탕으로 애플리케이션을 개발 | 아마존 EC2 |
| **PaaS** (Platform as a Service) | 개발자에게 애플리케이션을 개발·테스트·배포하기 위한 환경을 제공. 개발에만 집중할 수 있도록 도움 | AWS 엘라스틱 빈스토크, 아마존 S3 |
| **SaaS** (Software as a Service) | 최종 사용자를 위한 소프트웨어를 의미. 사용자는 웹사이트나 애플리케이션을 통해 소프트웨어에 접근 | 구글 닥스(Google Docs) |

## 14.2 이벤트 기반 코드 실행 서비스, AWS 람다 살펴보기

AWS 람다는 이벤트 기반 아키텍처를 기반으로 하며, 특정 이벤트가 발생하면 해당 이벤트를 처리하는 별도의 함수를 생성해 실행하는 서버리스 컴퓨팅 서비스다. 함수는 특정 이벤트에 대한 핸들러로 구성되어 있으며, 이벤트가 발생하면 핸들러가 실행되어 코드를 실행하는 구조다.

### 14.2.1 이벤트 기반 코드 실행 서비스, AWS 람다 이점

AWS 람다를 사용함으로써 얻을 수 있는 이점은 크게 다섯 가지다.

1. **비용 절감**
2. **보다 안전한 실행 환경**
3. **장애 위험 부담 감소**
4. **다양한 프로그래밍 언어 제공**
5. **다른 AWS 서비스와의 연동**

### 비용 절감

AWS 람다는 **코드 실행 시간과 요청 수에 따라** 비용이 청구된다. 따라서 실행되지 않는 때는 비용이 발생하지 않기 때문에, 이벤트가 많지만 실행 시간이 짧은 경우 비용이 절감될 수 있다. 또한 아마존 EC2와 달리 별도의 서버를 준비할 필요가 없어 서버 관리 비용도 절감할 수 있다.

### 보다 안전한 실행 환경

AWS 람다는 AWS에서 실행 환경을 관리하기 때문에, 개발자가 개인이나 회사에서 직접 실행 환경을 관리하는 것보다 안전한 환경에서 코드를 실행할 수 있다. AWS는 보안 전문가 팀이 24시간 시스템을 모니터링해 관리하므로 사용자는 관리에 대해 걱정할 필요가 없다.

### 장애 위험 부담 감소

온프레미스 환경이나 자체 서버를 운용하는 경우 서버의 준비·운영·장애 대응까지 모두 직접 처리해야 한다. 하지만 AWS 람다를 사용하면 AWS가 서버 관리를 담당하므로, 람다 함수 하나에 장애가 발생해도 AWS가 대응한다.

### 다양한 프로그래밍 언어 제공

AWS 람다는 다양한 프로그래밍 언어와 프레임워크를 제공하며, 사용자는 직접 코드를 작성하거나 AWS에서 제공하는 템플릿을 사용해 람다 함수를 생성할 수 있다.

### 다른 AWS 서비스와의 연동

AWS 람다는 다른 AWS 서비스와 연동해 더 다양한 작업을 처리할 수 있다. 예를 들어 **S3 웹 호스팅**을 구현하거나 **서버리스 웹 호스팅**을 구현할 수 있다.

```
[S3 웹 호스팅]
아마존 S3 → 아마존 API 게이트웨이 → AWS 람다 → 아마존 다이나모DB

[앰플리파이 웹 호스팅]
AWS 앰플리파이 → 아마존 API 게이트웨이 → AWS 람다 → 아마존 다이나모DB
```

AWS 람다에서 아마존 다이나모DB에 저장된 데이터를 가져와, 웹사이트를 호스팅하는 아마존 S3 혹은 AWS 앰플리파이에 출력할 수 있다. 람다 함수가 데이터를 처리하고 처리된 결과를 웹페이지에 동적으로 표시할 수 있어, 웹 애플리케이션의 데이터 업데이트 및 실시간 반영 등 다양한 기능을 구현할 수 있다. 또한 AWS 서비스 이외에도 다양한 라이브러리, 서비스와도 연동할 수 있다.

> 💡 슬랙과 같은 커뮤니케이션 도구와 연동해 AWS 사용 요금 혹은 EC2 인스턴스의 중지와 실행 이벤트 등 여러 알림을 받아볼 수 있도록 설정할 수 있다.
>

### 14.2.2 이벤트 기반 코드 실행 서비스, AWS 람다 구성 요소

AWS 람다를 사용하려면 함수를 생성할 필요가 있다. 람다 함수에는 **[새로 작성]**, **[블루프린트 사용]**, **[컨테이너 이미지]** 세 가지 함수 유형이 있다.

### AWS 람다 함수 새로 작성

새로 작성하는 람다 함수의 기본 구성은 다음과 같다.

```
AWS 람다
 ├─ 함수 이름
 ├─ 런타임
 ├─ 아키텍처
 └─ 권한
```

- **런타임**: 함수에서 사용하는 프로그래밍 언어 또는 프레임워크의 버전을 의미한다. 2025년 기준 지원하는 최신 버전은 다음과 같다.
    - .NET 8 (C#/F#/파워셸)
    - 자바 21
    - Node.js 22.x
    - 파이썬 3.13
    - 루비 3.4
    - 아마존 리눅스 2023
- **아키텍처**: 사용하고자 하는 컴퓨터 프로세서의 유형을 선택할 수 있으며, **x86_64** 와 **arm64** 중 선택할 수 있다.
- **권한**: 람다 함수에 부여할 권한을 선택할 수 있다. 람다 함수는 다양한 AWS 서비스와 연동되어 사용될 수 있기 때문에, 연동하려는 각 서비스에 대한 권한이 필요하다. 이 권한은 **IAM 서비스**를 이용해 부여할 수 있다. 이런 권한 설정을 통해 람다 함수는 다른 AWS 서비스를 호출하거나 특정 작업을 수행할 수 있다.

### AWS 람다 함수 블루프린트 사용

블루프린트를 사용하면 람다 함수에서 **샘플 코드를 제공받아** 더 간편하게 함수를 작성할 수 있다.

```
AWS 람다
 ├─ 함수 이름
 ├─ 런타임 ── (런타임 / 아키텍처 자동 결정)
 └─ 권한
```

블루프린트는 **함수 이름, 블루프린트 이름, 권한** 세 가지로 구성되어 있다. 새로 작성하는 경우 런타임과 아키텍처를 직접 설정해야 했지만, **블루프린트를 선택하면 자동으로 런타임과 아키텍처가 결정**된다.

- 블루프린트에서는 다양한 사용 사례에 따른 템플릿을 선택할 수 있다.
- 선택한 템플릿에 따라 람다 함수 코드가 자동으로 작성된다.

이런 블루프린트를 사용하면 사용 사례에 적합한 람다 함수를 빠르게 작성할 수 있으며, 개발자는 제공된 코드를 받아 더 빠르고 유연하게 코드를 작성할 수 있다.

### AWS 람다 함수 컨테이너 이미지

컨테이너 이미지는 람다 함수를 컨테이너화하는 것으로, 아마존 ECR에 푸시한 이미지를 AWS에 배포할 수 있다.

```
AWS 람다
 ├─ 함수 이름
 ├─ 컨테이너 이미지 URI
 ├─ 아키텍처
 └─ 권한
```

기존 람다 함수를 사용할 때는 외부 라이브러리나 미들웨어를 도입하는 경우, 라이브러리 버전이 일치해야 하거나 특정 미들웨어를 도입해야 하는 등의 문제가 발생할 수 있다. 하지만 람다 함수에서 컨테이너 이미지를 사용하면 이런 문제를 해결할 수 있다. 컨테이너 이미지는 함수 이름과 컨테이너 이미지 URI, 아키텍처, 권한으로 구성되어 있으며, 컨테이너 이미지 URI를 요구하기 때문에 사전에 아마존 ECR로 이미지를 푸시할 필요가 있다.

> 💡 여러 함수에 라이브러리를 공유하는 방법으로 **람다 계층(Lambda Layers)** 이라는 기능을 사용하는 방법도 있다. 람다 계층을 사용하면 람다 함수에서 필요로 하는 외부 라이브러리나 미들웨어를 별도로 관리할 수 있다.

## 14.3 AWS 람다 함수 생성해보기

이번 실습에서는 클라우드포메이션 스택으로 AWS 람다 함수를 생성해 간단하게 Hello World를 출력한다.

### 14.3.1 AWS 람다 함수로 Hello World 출력해보기

> **To do 01** AWS 람다 함수로 Hello World를 출력하는 클라우드포메이션의 yml 파일은 다음과 같다.
>
> - 파일 이름: `lambda.yml`
> - 클라우드포메이션 전체 코드는 깃허브 리포지터리 `[chapter14] → [Lambda] → [chapter14.3.1-Create-Lambda]` 폴더에서 확인할 수 있다.

### 02 람다에서 사용하기 위한 IAM 역할 생성

```yaml
# lambda.yml
LambdaIAMRole:
  Type: AWS::iam::Role
  DeletionPolicy: Delete
  Properties:
    RoleName: !Sub ${SystemName}-${EnvName}-lambdarole
    AssumeRolePolicyDocument:
      Version: "2012-10-17"
      Statement:
        - Effect: "Allow"
          Principal:
            Service:
              - "lambda.amazonaws.com"
          Action:
            - "sts:AssumeRole"
    Path: "/"
    ManagedPolicyArns:
      - "arn:aws:iam::aws:policy/AWSLambda_FullAccess"  # ❶ 람다 함수의 모든 권한을 가진 IAM 역할
```

람다 함수에서는 반드시 IAM 역할을 지정해야 한다. AWS 콘솔로 람다 함수를 생성하면서 [기본 Lambda 권한을 가진 새 역할 생성] 옵션을 지정하면 사용자가 직접 IAM 역할을 생성할 필요는 없지만, 클라우드포메이션에서는 사용자가 직접 IAM 역할을 생성할 필요가 있다.

### 03 람다 함수 생성

```yaml
# lambda.yml
LambdaFunction:
  Type: AWS::lambda::Function  # ❶ Type에는 AWS::lambda::Function을 입력해 람다 함수를 생성
  Properties:
    FunctionName: !Sub ${SystemName}-${EnvName}-function
    Code:  # ❷ 속성에서는 Code를 지정해 람다 함수에서 실행할 코드를 입력
      ZipFile: |
        import json

        def lambda_handler(event, context):
            # TODO implement
            return {
                'statusCode': 200,
                'body': json.dumps('Hello from Lambda!')
            }
    Handler: index.lambda_handler  # ❸ Handler는 람다가 실행할 메서드 이름
    Role: !GetAtt LambdaIAMRole.Arn  # ❹ Role은 조금 전 생성한 IAM 역할을 지정
    Runtime: python3.12  # ❺ Runtime에는 Python 3.12를 선택
    Timeout: 30  # ❻ Timeout은 Lambda가 함수를 중지하기 전에 실행할 수 있는 시간을 의미
```

코드 설명:

- ❶ **Type**: `AWS::lambda::Function`을 입력해 람다 함수를 생성한다.
- ❷ **Code**: 속성에서 Code를 지정해 람다 함수에서 실행할 코드를 입력한다. 현재 입력한 코드는 "Hello from Lambda!"를 출력하는 간단한 코드다.
- ❸ **Handler**: 람다가 실행할 메서드 이름이다.
- ❹ **Role**: 조금 전 생성한 IAM 역할을 지정한다.
- ❺ **Runtime**: Python 3.12를 선택한다.
- ❻ **Timeout**: Lambda가 함수를 중지하기 전에 실행할 수 있는 시간을 의미한다.

### 14.3.2 UI로 불러와 AWS 람다 함수로 Hello World 출력해보기

이번에는 람다 함수를 생성하기 위한 클라우드포메이션 스택을 생성하고, 람다 함수를 실행해 "Hello world"를 출력해본다.

### 01 클라우드포메이션 스택 생성

클라우드포메이션 스택에는 별다른 파라미터 설정값이 없으므로 기본값을 유지한 상태로 스택을 생성한다.

- **스택 이름**: `gr-lambda`
- **파라미터**: 템플릿에서 정의되며, 스택을 생성하거나 업데이트할 때 사용자 지정 값을 입력할 수 있다.
    - `EnvName`: `product` (Environment name of each resource names)
    - `SystemName`: `gr` (System name of each resource names)

### 02 람다 콘솔 화면 진입

AWS 관리 콘솔에서 AWS 람다 콘솔 화면으로 진입한다.

1. AWS 람다 콘솔 화면에서 [함수]를 클릭한다.
2. 생성된 람다 함수(`gr-product-function`)를 확인한다.

### 03 람다 함수 정보 확인 및 코드 실행

생성한 람다 함수 정보를 확인하고 코드를 실행한다.

1. 람다 함수를 생성하면 **함수 개요**가 출력되며, 현재 람다 함수에서 사용하는 람다 계층(예: 라이브러리 등)과 연동하는 AWS 서비스를 확인할 수 있다.
2. **코드** 카테고리를 클릭하면 파이썬 코드를 확인할 수 있다.
3. 해당 람다 함수를 실행하기 위해 **[Test]** 를 클릭한다. [Test]를 클릭하면 람다 함수의 이벤트를 생성하거나 기존 이벤트를 선택할 수 있다. 생성한 이벤트가 없으므로 새로 생성한다(Create new test event).

### 04 람다 함수의 이벤트 생성

1. 람다 함수의 이벤트 이름을 입력한다. (예: `gr-test-event`, 최대 25자 / 문자·숫자·점·하이픈·언더스코어)
2. 템플릿의 경우 "hello-world"를 출력하는 디폴트 템플릿을 선택한다. 현재 "Hello from Lambda" 텍스트를 출력하는 간단한 코드이기 때문에 '이벤트 JSON'에 생성된 key와 value를 받아 출력하는 부분은 불필요하다. 이대로 기본값을 유지한 상태로 **[Save]** 를 클릭한다.

```json
{
  "key1": "value1",
  "key2": "value2",
  "key3": "value3"
}
```

### 05 람다 함수 실행 및 결과 확인

람다 함수를 실행해 결과를 확인한다.

1. 이벤트를 생성했다면 다시 **[Test]** 를 클릭해 결과를 확인한다.
2. **Response** 로 "Hello from Lambda"가 출력된 것을 확인할 수 있다.

```
Status: Succeeded
Test Event Name: gr-test-event

Response:
{
  "statusCode": 200,
  "body": "\"Hello from Lambda!\""
}
```

## 학습 마무리

이번 장에서는 이벤트 기반 코드 실행 백엔드 서비스인 AWS 람다를 학습했다. AWS 람다를 학습하기에 앞서 서버리스가 무엇인지, 또한 FaaS가 무엇인지, AWS 람다가 가지는 이점과 구성에 대해 학습했다.

### 핵심 요약

1. **AWS 람다**는 AWS에서 제공하는 서버리스 서비스로, 서버를 구축하지 않고도 작성한 코드를 실행할 수 있는 이벤트 구동형 프로그램 실행 환경이다.
2. AWS 람다는 넓은 의미에서는 서버리스로 표현하며, 보다 좁은 의미로는 **FaaS(Functions-as-a-Service)** 로 표현할 수 있다. 서버리스는 다양한 서비스 범주에 중점을 두며, 여기에는 스토리지, 데이터베이스, 컴퓨팅 등이 포함된다. 이런 서버리스 환경에는 FaaS도 포함되어 있다.
3. 람다 함수에는 **새로 작성, 블루프린트 사용, 컨테이너 이미지** 세 가지 함수 유형이 있다.
    - **블루프린트**는 적합한 사용 사례를 선택하고, 이에 맞추어 코드를 제공받아 더 간편하게 함수를 작성할 수 있다.
    - **컨테이너 이미지**는 람다 함수를 컨테이너화하는 것으로, 아마존 ECR에 푸시한 이미지를 AWS에 배포할 수 있다.
