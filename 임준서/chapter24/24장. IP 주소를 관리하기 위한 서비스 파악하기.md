## 개요

이번 장에서는 여러 IP 주소를 하나의 집합으로 관리할 수 있는 **관리형 접두사 목록(Managed Prefix List)**을 학습한다.

관리형 접두사 목록을 사용하면 다수의 IP 주소를 보안 그룹이나 라우팅 테이블에 일일이 등록하지 않고 하나의 리소스로 묶어 관리할 수 있다.

주요 학습 내용은 다음과 같다.

- 관리형 접두사 목록의 개념
- 다수 IP 주소를 개별 관리할 때의 문제
- 고객 관리형 접두사 목록
- AWS 관리형 접두사 목록
- 보안 그룹에서 관리형 접두사 목록 활용
- CloudFormation을 이용한 접두사 목록 생성

---

## 24.1 IP 주소를 관리하는 서비스, 관리형 접두사 목록이란?

### 관리형 접두사 목록의 개념

관리형 접두사 목록은 하나 이상의 IP 주소 범위인 **CIDR 블록의 집합**이다.

생성한 접두사 목록은 다음 리소스의 규칙에서 사용할 수 있다.

- 보안 그룹
- 라우팅 테이블

예를 들어 다음 네 개의 IP 주소에 대해 SSH 접속을 허용한다고 가정한다.

```
1.2.3.4/32
1.3.4.4/32
2.3.4.4/32
3.3.4.4/32
```

관리형 접두사 목록을 사용하지 않으면 보안 그룹에 네 개의 인바운드 규칙을 각각 추가해야 한다.

```
SSH TCP 22 1.2.3.4/32
SSH TCP 22 1.3.4.4/32
SSH TCP 22 2.3.4.4/32
SSH TCP 22 3.3.4.4/32
```

관리형 접두사 목록을 사용하면 네 IP 주소를 하나의 목록으로 묶고, 보안 그룹에는 해당 목록을 참조하는 규칙 하나만 추가할 수 있다.

```
관리형 접두사 목록
├── 1.2.3.4/32
├── 1.3.4.4/32
├── 2.3.4.4/32
└── 3.3.4.4/32

보안 그룹
└── SSH TCP 22 → 관리형 접두사 목록
```

---

## 관리형 접두사 목록이 필요한 이유

환경이 커지면 관리해야 할 IP 주소 수가 계속 증가한다.

예를 들어 SSH 접속을 허용해야 하는 IP 주소가 네 개에서 여섯 개, 여덟 개로 증가하면 보안 그룹 규칙도 IP 주소마다 추가해야 한다.

이 방식은 다음과 같은 문제를 만든다.

- 보안 그룹 규칙 수 증가
- 같은 IP 목록을 여러 보안 그룹에 반복 등록
- IP 변경 시 모든 보안 그룹을 각각 수정
- 전체 허용 IP 목록 파악의 어려움
- 규칙 누락 또는 오입력 가능성
- 보안 정책 유지보수 비용 증가
- 가독성 저하

관리형 접두사 목록을 사용하면 IP 주소의 집합을 별도로 관리하고, 보안 그룹과 라우팅 테이블은 해당 목록만 참조하게 할 수 있다.

---

### 관리형 접두사 목록 사용 전

```
보안 그룹 A
├── IP 1
├── IP 2
├── IP 3
└── IP 4

보안 그룹 B
├── IP 1
├── IP 2
├── IP 3
└── IP 4
```

IP 주소가 변경되면 두 보안 그룹을 모두 수정해야 한다.

---

### 관리형 접두사 목록 사용 후

```
관리형 접두사 목록
├── IP 1
├── IP 2
├── IP 3
└── IP 4

보안 그룹 A ──→ 관리형 접두사 목록
보안 그룹 B ──→ 관리형 접두사 목록
```

IP 주소가 변경되면 접두사 목록만 수정하면 이를 참조하는 리소스에 일관되게 반영할 수 있다.

---

## 24.2 관리형 접두사 목록 살펴보기

관리형 접두사 목록은 다음 두 종류로 구분된다.

1. 고객 관리형 접두사 목록
2. AWS 관리형 접두사 목록

---

## 24.2.1 고객 관리형 접두사 목록

고객 관리형 접두사 목록은 사용자가 직접 생성하고 관리하는 IP 주소 집합이다.

사용자는 다음 작업을 수행할 수 있다.

- 접두사 목록 생성
- CIDR 항목 추가
- CIDR 항목 수정
- CIDR 항목 삭제
- 최대 항목 수 지정
- 다른 AWS 계정과 공유
- 보안 그룹과 라우팅 테이블에서 참조

```
사용자
  ↓
고객 관리형 접두사 목록 생성
  ↓
CIDR 주소 등록
  ↓
보안 그룹 또는 라우팅 테이블에서 참조
```

예시는 다음과 같다.

```
고객 관리형 접두사 목록: office-ssh-ips

1.2.3.4/32
1.3.4.4/32
2.3.4.4/32
3.3.4.4/32
```

이 목록을 보안 그룹의 SSH 인바운드 규칙에 연결하면 해당 목록에 포함된 IP 주소만 22번 포트에 접근할 수 있다.

---

## 24.2.2 AWS 관리형 접두사 목록

AWS 관리형 접두사 목록은 AWS 서비스가 사용하는 IP 주소 범위를 AWS가 미리 관리하는 목록이다.

사용자가 직접 항목을 생성하거나 수정하거나 삭제할 수 없다.

대표적으로 다음 AWS 서비스의 IP 주소 범위를 접두사 목록으로 제공한다.

- Amazon CloudFront
- Amazon DynamoDB
- AWS Ground Station
- Amazon Route 53
- Amazon S3
- Amazon S3 Express One Zone
- Amazon VPC Lattice

AWS 관리형 접두사 목록은 다음과 같은 상황에서 사용할 수 있다.

- CloudFront에서 전달되는 트래픽만 허용
- VPC 엔드포인트를 통해 S3로 가는 트래픽 설정
- DynamoDB 서비스 주소로 향하는 경로 설정
- AWS 서비스의 IP 주소 변경을 자동으로 반영

---

### 고객 관리형과 AWS 관리형 비교

| 구분 | 고객 관리형 접두사 목록 | AWS 관리형 접두사 목록 |
| --- | --- | --- |
| 생성 주체 | 사용자 | AWS |
| IP 주소 관리 | 사용자가 직접 관리 | AWS가 자동 관리 |
| 수정 가능 여부 | 추가, 수정, 삭제 가능 | 사용자 수정 불가 |
| 주요 대상 | 사내 IP, 협력사 IP, 관리자 IP | S3, CloudFront 등 AWS 서비스 |
| 보안 그룹 사용 | 가능 | 가능 |
| 라우팅 테이블 사용 | 가능 | 가능 |
| 공유 | 다른 계정과 공유 가능 | AWS가 제공 |
| 주요 장점 | 조직의 IP 정책을 중앙에서 관리 | AWS 서비스 IP 변경을 직접 관리할 필요 없음 |

---

## 관리형 접두사 목록의 장점

### 규칙 단순화

여러 IP 주소를 보안 그룹 규칙 하나로 관리할 수 있다.

```
사용 전: IP 주소 4개 → 보안 그룹 규칙 4개
사용 후: 접두사 목록 1개 → 보안 그룹 규칙 1개
```

---

### 일관된 보안 정책

여러 보안 그룹에서 동일한 접두사 목록을 참조할 수 있다.

IP 목록이 변경되더라도 각 보안 그룹을 개별적으로 수정할 필요가 없다.

---

### 유지보수성 향상

허용할 IP 주소를 한곳에서 관리하므로 다음 효과를 얻을 수 있다.

- 규칙 가독성 향상
- 중복 설정 감소
- 누락 위험 감소
- 운영자의 수정 작업 감소
- 정책 변경의 중앙 관리

---

### 확장성 향상

IP 주소 수가 증가해도 접두사 목록에 항목을 추가하는 방식으로 확장할 수 있다.

단, 접두사 목록의 `MaxEntries` 값은 보안 그룹 규칙 할당량에 영향을 줄 수 있으므로 지나치게 크게 설정하지 않도록 주의해야 한다.

---

### 재사용성

하나의 접두사 목록을 여러 리소스에서 재사용할 수 있다.

```
관리형 접두사 목록
 ├── 보안 그룹 A
 ├── 보안 그룹 B
 ├── 보안 그룹 C
 └── 라우팅 테이블
```

---

## 24.3 관리형 접두사 목록 활용하기

이번 실습에서는 고객 관리형 접두사 목록을 생성하고 보안 그룹의 인바운드 규칙에 추가한다.

전체 흐름은 다음과 같다.

```
고객 관리형 접두사 목록 생성
  ↓
허용할 IPv4 CIDR 주소 등록
  ↓
보안 그룹 인바운드 규칙에 접두사 목록 지정
  ↓
CloudFormation 스택 생성
  ↓
VPC 콘솔에서 접두사 목록 확인
  ↓
보안 그룹에서 적용 여부 확인
```

---

## 24.3.1 CloudFormation으로 고객 관리형 접두사 목록 생성하기

고객 관리형 접두사 목록은 `AWS::EC2::PrefixList` 리소스로 생성한다.

```
PrefixList:
  Type: AWS::EC2::PrefixList
  Properties:
    AddressFamily: IPv4
    Entries:
      - Cidr: 1.2.3.4/32
      - Cidr: 1.3.2.4/32
      - Cidr: 1.4.2.4/32
      - Cidr: 1.5.3.5/32
    MaxEntries: 4
    PrefixListName:!Sub ${SystemName}-${EnvName}-prefix
```

---

### Type

```
Type: AWS::EC2::PrefixList
```

고객 관리형 접두사 목록을 생성한다.

---

### AddressFamily

```
AddressFamily: IPv4
```

접두사 목록에서 사용하는 IP 주소 체계를 지정한다.

선택 가능한 값은 다음과 같다.

- `IPv4`
- `IPv6`

---

### Entries

```
Entries:
  - Cidr: 1.2.3.4/32
  - Cidr: 1.3.2.4/32
  - Cidr: 1.4.2.4/32
  - Cidr: 1.5.3.5/32
```

접두사 목록에 포함할 CIDR 주소를 지정한다.

`/32`는 하나의 IPv4 주소만 정확히 지정하는 CIDR 표기이다.

```
1.2.3.4/32
→ 1.2.3.4 한 개의 IP 주소
```

여러 주소 범위를 등록하려면 더 넓은 CIDR을 지정할 수도 있다.

```
10.0.0.0/24
→ 10.0.0.0부터 10.0.0.255까지의 주소 범위
```

---

### MaxEntries

```
MaxEntries: 4
```

접두사 목록에 추가할 수 있는 최대 항목 수이다.

현재 항목이 네 개라면 최소 4 이상으로 설정해야 한다.

`MaxEntries`는 보안 그룹 규칙 수 계산과 관련될 수 있으므로, 실제 필요 이상으로 크게 설정하지 않는 것이 좋다.

---

### PrefixListName

```
PrefixListName:!Sub ${SystemName}-${EnvName}-prefix
```

접두사 목록의 이름을 지정한다.

`!Sub`를 사용하여 시스템 이름과 환경 이름을 조합할 수 있다.

```
gr-product-prefix
```

---

## 보안 그룹에 접두사 목록 추가하기

생성한 고객 관리형 접두사 목록을 보안 그룹 인바운드 규칙의 소스로 지정한다.

```
SecurityGroupIngress:
  - IpProtocol: tcp
    FromPort: 22
    ToPort: 22
    SourcePrefixListId:
      Fn::ImportValue:!Sub ${EnvName}-prefix
```

---

### IpProtocol

```
IpProtocol: tcp
```

SSH는 TCP 프로토콜을 사용하므로 `tcp`로 설정한다.

---

### FromPort와 ToPort

```
FromPort: 22
ToPort: 22
```

22번 포트에 대한 접근을 허용한다.

---

### SourcePrefixListId

```
SourcePrefixListId:
  Fn::ImportValue:!Sub ${EnvName}-prefix
```

보안 그룹에서 허용할 출발지로 고객 관리형 접두사 목록을 지정한다.

기존에는 IP 주소마다 별도의 규칙이 필요했지만, 이제 접두사 목록을 가리키는 규칙 하나만으로 여러 IP 주소를 허용할 수 있다.

---

## CloudFormation 스택 간 값 공유

접두사 목록과 보안 그룹을 서로 다른 CloudFormation 스택에서 생성하면, 접두사 목록 ID를 출력값으로 내보낸 뒤 다른 스택에서 가져올 수 있다.

### 접두사 목록 스택

```
Outputs:
  PrefixListId:
    Value:!Ref PrefixList
    Export:
      Name:!Sub ${EnvName}-prefix
```

### 보안 그룹 스택

```
SourcePrefixListId:
  Fn::ImportValue:!Sub ${EnvName}-prefix
```

이를 통해 네트워크 공통 리소스와 애플리케이션 보안 그룹을 서로 다른 스택으로 분리할 수 있다.

---

## 24.3.2 AWS 콘솔에서 접두사 목록 확인하기

CloudFormation 스택 생성 후 다음 과정으로 접두사 목록을 확인할 수 있다.

1. AWS VPC 콘솔로 이동
2. **관리형 접두사 목록** 메뉴 선택
3. 생성한 고객 관리형 접두사 목록 확인
4. 목록의 상세 정보 선택
5. 등록된 CIDR 항목 확인
6. 연결 탭에서 접두사 목록을 사용하는 리소스 확인

상세 화면에서는 다음 항목을 확인할 수 있다.

- 접두사 목록 ID
- 접두사 목록 이름
- 주소 패밀리
- 상태
- 최대 항목 수
- 현재 버전
- 등록된 CIDR 항목
- 연결된 리소스
- 공유 및 태그 정보

---

## 접두사 목록의 연결 정보

접두사 목록의 **연결** 탭에서는 해당 목록을 참조하는 AWS 리소스를 확인할 수 있다.

예를 들어 보안 그룹에서 사용 중이라면 다음 정보가 표시된다.

```
리소스 유형: Security Group
리소스 ID: sg-xxxxxxxx
```

이를 통해 특정 접두사 목록이 어디에서 사용되고 있는지 추적할 수 있다.

---

## 보안 그룹 적용 결과 확인

보안 그룹의 인바운드 규칙을 확인하면 출발지에 개별 IP 주소가 아닌 접두사 목록 ID가 표시된다.

```
유형: SSH
프로토콜: TCP
포트 범위: 22
소스: pl-xxxxxxxx
```

접두사 목록에 네 개의 IP 주소가 등록되어 있더라도 보안 그룹에는 하나의 규칙만 존재한다.

```
기존 방식
IP 4개 → 인바운드 규칙 4개

접두사 목록 방식
IP 4개 → 접두사 목록 1개 → 인바운드 규칙 1개
```

이를 통해 보안 그룹 구성이 단순해지고 유지 관리가 쉬워진다.

---

## 관리형 접두사 목록 사용 시 고려사항

### CIDR 범위 최소화

필요 이상으로 넓은 CIDR 범위를 등록하면 불필요한 IP 주소에도 접근이 허용될 수 있다.

```
권장: 1.2.3.4/32
주의: 0.0.0.0/0
```

최소 권한 원칙에 따라 실제로 필요한 IP 주소와 네트워크 범위만 등록해야 한다.

---

### MaxEntries 설정

`MaxEntries`는 현재 등록된 주소 수보다 작을 수 없다.

필요 이상으로 크게 지정하면 보안 그룹 규칙 할당량을 불필요하게 사용할 수 있으므로 적절한 크기를 설정해야 한다.

---

### 변경 관리

접두사 목록 하나가 여러 보안 그룹과 라우팅 테이블에서 사용될 수 있다.

따라서 접두사 목록의 CIDR을 변경하면 여러 리소스에 동시에 영향을 줄 수 있다.

변경 전 다음 내용을 확인해야 한다.

- 연결된 보안 그룹
- 연결된 라우팅 테이블
- 삭제하려는 IP 주소의 실제 사용 여부
- 신규 IP 주소의 신뢰 여부
- 변경으로 인한 서비스 접근 차단 가능성

### 고객 관리형과 AWS 관리형의 구분

조직이 직접 관리하는 IP 주소에는 고객 관리형 접두사 목록을 사용한다.

AWS 서비스의 IP 주소 범위에는 가능하면 AWS 관리형 접두사 목록을 사용한다. AWS 서비스의 주소 변경을 사용자가 직접 추적하지 않아도 되기 때문이다.

## 24장 학습 마무리

관리형 접두사 목록은 여러 CIDR 주소를 하나의 집합으로 관리하는 기능이다.

이를 보안 그룹과 라우팅 테이블에서 사용하면 여러 IP 주소에 대한 규칙을 반복해서 생성하지 않아도 된다.

고객 관리형 접두사 목록은 사용자가 직접 IP 주소를 관리하며, AWS 관리형 접두사 목록은 AWS 서비스의 IP 주소 범위를 AWS가 관리한다.

관리형 접두사 목록을 적용하면 다음 효과를 얻을 수 있다.

- 보안 그룹 규칙 단순화
- 중복된 IP 설정 감소
- 보안 정책 중앙 관리
- IP 주소 변경 작업 감소
- 가독성 및 유지보수성 향상
- 여러 리소스에서 동일한 IP 정책 재사용

## Chapter 24 핵심 요약

1. 관리형 접두사 목록은 하나 이상의 CIDR 주소를 묶은 IP 주소 집합이다.
2. 접두사 목록은 보안 그룹과 라우팅 테이블에서 사용할 수 있다.
3. 고객 관리형 접두사 목록은 사용자가 직접 생성하고 수정하는 목록이다.
4. AWS 관리형 접두사 목록은 AWS 서비스의 IP 주소 범위를 AWS가 관리하는 목록이다.
5. 접두사 목록을 사용하면 여러 IP 주소를 보안 그룹 규칙 하나로 관리할 수 있다.
6. 고객 관리형 접두사 목록은 CloudFormation의 `AWS::EC2::PrefixList`로 생성한다.
7. 보안 그룹에서는 `SourcePrefixListId`를 이용하여 접두사 목록을 참조할 수 있다.
8. 접두사 목록을 변경하면 이를 참조하는 여러 리소스에 영향을 줄 수 있으므로 연결 관계를 확인해야 한다.
